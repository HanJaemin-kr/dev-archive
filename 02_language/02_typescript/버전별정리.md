# TypeScript 버전별 기능 정리 (4.0 ~ 7.0)

> 읽는 법
> - ⭐ = 실무/면접에서 자주 나오는 "꼭 알아야 할" 기능
> - 각 항목은 **무엇이 추가됐나 → 왜 중요한가 → 짧은 예제** 순
> - 버전 규칙: TS는 `5.x`처럼 마이너 단위로 신기능이 들어감. 시맨틱 버저닝 아님(마이너에도 파괴적 변경 있을 수 있음)
> - 큰 흐름: **4.x = 타입 시스템 표현력 폭발 → 5.x = 표준 문법 흡수(데코레이터/using 등) → 6.0 = 정리·전환 → 7.0 = Go 네이티브 재작성**

## TypeScript 4.x 계열 — 타입 시스템 표현력의 확장

### 4.0 (2020.08)

- **Variadic Tuple Types** — 튜플에 스프레드(`...`)를 써서 가변 길이 튜플을 조합
- **Labeled Tuple Elements** — 튜플 각 요소에 이름 부여(가독성/힌트)
- **단축 할당 연산자** `&&=` `||=` `??=`

```ts
type Range = [start: number, end: number];      // 라벨 튜플
function concat<T extends any[], U extends any[]>(a: T, b: U): [...T, ...U] {
  return [...a, ...b];
}
a ??= b;   // a가 null/undefined일 때만 b 대입
```

### 4.1 (2020.11) ⭐

- **Template Literal Types** — 문자열 리터럴 타입을 조합해 새 문자열 타입 생성
- **Key Remapping in Mapped Types** — 매핑 타입에서 `as`로 키 이름 변형
- **Recursive Conditional Types** — 조건부 타입 재귀 허용
- `--noUncheckedIndexedAccess` (인덱스 접근 결과에 `undefined` 포함)

```ts
type Event = `on${Capitalize<'click' | 'focus'>}`;   // "onClick" | "onFocus"
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
```

### 4.2 (2021.02)

- 튜플의 **앞/중간 rest 요소** 허용 (`[...string[], number]`)
- `abstract` 생성자 시그니처
- 타입 별칭(alias) 이름을 에러/호버에 더 잘 보존

```ts
type T = [...string[], number];   // 마지막이 number인 가변 튜플
```

### 4.3 (2021.05) ⭐

- **`override` 키워드** + `--noImplicitOverride` — 부모에 없는 메서드를 오버라이드하면 에러
- getter/setter에 **서로 다른 타입** 허용
- `#private` 메서드/접근자, `static` 인덱스 시그니처

```ts
class Base { greet() {} }
class Derived extends Base {
  override greet() {}   // 부모에 greet 없으면 컴파일 에러
}
```

### 4.4 (2021.08)

- **별칭 조건/판별자에 대한 흐름 분석(CFA)** — 조건을 변수에 담아도 좁혀짐
- `--exactOptionalPropertyTypes` (`?` 속성에 `undefined` 명시적 대입 구분)
- 클래스 **static 블록**
- `strict`에서 `catch` 변수 기본 타입이 `unknown`으로

```ts
const isString = typeof x === 'string';
if (isString) x.toUpperCase();   // x가 string으로 좁혀짐 (별칭이어도 OK)
```

### 4.5 (2021.11)

- **`Awaited<T>`** 유틸리티 타입 (중첩 Promise 언랩)
- **import 문에 `type` 수식어** (`import { type A, b }`)
- private 필드 존재 검사(`#x in obj`)

```ts
type R = Awaited<Promise<Promise<number>>>;   // number
import { type User, createUser } from './user';
```

### 4.6 (2022.02)

- **구조 분해된 판별 유니온**에 흐름 분석 적용
- `super()` 호출 전 코드 일부 허용, 재귀 깊이 검사 개선

```ts
type Action = { kind: 'a'; a: number } | { kind: 'b'; b: string };
function run({ kind, a, b }: Action) {
  if (kind === 'a') a.toFixed();   // 구조 분해 후에도 좁혀짐
}
```

### 4.7 (2022.05) ⭐

- **Node.js ESM 지원** — `--module node16`/`nodenext`, `package.json`의 `exports`/`imports`, `.mts`/`.cts`
- **Instantiation Expressions** — 제네릭에 타입 인자만 미리 고정
- `infer`에 `extends` 제약, 타입 매개변수 **변성 표기** `in`/`out`

```ts
const makeStringBox = makeBox<string>;   // 함수를 타입 인자만 고정해 특수화
```

### 4.8 (2022.08)

- 교집합/유니온 및 `unknown` 좁히기 개선 (`unknown` ≈ `{} | null | undefined`)
- 추론 정확도·정합성 개선 (버그 픽스 성격)

### 4.9 (2022.11) ⭐⭐

- **`satisfies` 연산자** — 값이 특정 타입을 "만족"하는지 검사하되, **좁은 리터럴 타입은 유지**
- `in` 연산자로 미기재 속성 좁히기, `NaN` 비교 에러 검출
- **`accessor`** 키워드(auto-accessor)

```ts
// 타입 체크는 하되, palette.red 는 [number,number,number] 로 그대로 유지됨
const palette = {
  red: [255, 0, 0],
  green: '#00ff00',
} satisfies Record<string, string | number[]>;
```

## TypeScript 5.x 계열 — 표준 JS 문법 흡수 & DX

### 5.0 (2023.03) ⭐⭐

- **표준 데코레이터(Stage 3)** — `--experimentalDecorators` 없이 사용
- **`const` 타입 매개변수** — 리터럴 타입을 넓히지 않고 추론
- 모든 enum이 유니온 enum으로, 패키지 경량화/속도 개선
- `--moduleResolution bundler`, `--verbatimModuleSyntax`, `export type *`

```ts
function first<const T>(arr: readonly T[]): T { return arr[0]; }
first(['a', 'b']);   // T = "a" | "b"  (const 없으면 string)

class MyClass {
  @logged method() {}   // 표준 데코레이터
}
```

### 5.1 (2023.06)

- `undefined` 반환 함수의 암시적 return 허용
- getter/setter 타입 무관 허용, **JSX 요소와 태그 타입 분리** (React 18 대응)

```ts
function f(): undefined { }   // return 문 없어도 OK
```

### 5.2 (2023.08) ⭐

- **`using` 선언 (명시적 리소스 관리)** — 스코프를 벗어날 때 `[Symbol.dispose]()` 자동 호출
- 데코레이터 메타데이터(`Symbol.metadata`), 튜플 라벨 혼용 허용

```ts
function getFile() {
  return { handle: 1, [Symbol.dispose]() { console.log('닫힘'); } };
}
{
  using file = getFile();   // 블록 종료 시 자동으로 dispose 호출
}   // → "닫힘"
```

### 5.3 (2023.11)

- **Import Attributes** — `with { type: "json" }` (구 `assert` 대체)
- `switch (true)` 패턴 좁히기, boolean 리터럴 비교 좁히기

```ts
import config from './config.json' with { type: 'json' };
```

### 5.4 (2024.03) ⭐

- **클로저 내 좁히기 보존** — 마지막 대입 이후 콜백에서도 타입 유지
- **`NoInfer<T>`** 유틸리티 — 특정 인자를 추론 소스에서 제외
- `Object.groupBy` / `Map.groupBy` 타입 추가

```ts
function createStreet<C extends string>(colors: C[], def: NoInfer<C>) {}
createStreet(['red', 'green'], 'red');   // def가 C 추론을 오염시키지 않음
```

### 5.5 (2024.06) ⭐⭐

- **추론된 타입 술어(Inferred Type Predicates)** — 반환 타입을 안 써도 `x is T`를 자동 추론
- 상수 인덱스 접근(`obj[key]`) 흐름 분석, **정규식 문법 검사**, `--isolatedDeclarations`

```ts
// 예전엔 결과가 (number|null)[] 였지만, 이제 filter가 술어를 추론 → number[]
const nums = [1, null, 2].filter(x => x !== null);
```

### 5.6 (2024.09) ⭐

- **Iterator Helpers** — 이터레이터에 `map`/`filter`/`take` 등 지연 평가 메서드 (중간 배열 미생성)
- 항상 truthy/nullish인 조건식 에러 검출, `IteratorObject` 타입 도입

```ts
// 중간 배열 없이 지연 평가
const result = [1, 2, 3, 4].values().map(x => x * 2).take(2).toArray();  // [2, 4]
```

### 5.7 (2024.11)

- `--target es2024` / `--lib es2024`
- **한 번도 초기화 안 된 변수** 사용 에러 검출
- `--rewriteRelativeImportExtensions` (소스엔 `.ts`로 쓰고 출력은 `.js`로)
- Node 22 V8 컴파일 캐시 지원, tsc 시작 속도 ~2.5x

```ts
let x: number;
console.log(x);   // 5.7부터 "초기화 전 사용" 에러
```

### 5.8 (2025.03) ⭐

- **`--erasableSyntaxOnly`** — 런타임 코드를 만드는 TS 전용 문법(enum·namespace·파라미터 프로퍼티)을 금지
  → Node.js가 타입만 지우고(type stripping) `.ts`를 **빌드 없이 직접 실행** 가능
- 조건부 return 분기별 정밀 검사, `nodenext`에서 ESM `require()` 지원

```ts
enum Color { Red }        // --erasableSyntaxOnly 켜면 에러 (런타임 코드 생성하므로)
type Color2 = 'red';      // 타입은 OK (지워지므로)
// 보통 --verbatimModuleSyntax 와 함께 사용
```

### 5.9 (2025.08)

- **`import defer`** — 모듈을 즉시 실행하지 않고 실제 사용 시점까지 지연(부작용/초기화 비용 제어)
- **`tsc --init` 재설계** (주석 덩어리 대신 최소 설정)
- 데코레이터 메타데이터 **정식(stable)** 승격, 호버 정보 개선, 인스턴스화 캐싱(성능)

```ts
import defer * as heavy from './heavy';   // 여기선 실행 안 됨
heavy.doWork();                            // 실제 접근 시 초기화
```

## TypeScript 6.0 (2026) — 마지막 JS 기반 / 7.0 전환 릴리스

7.0(네이티브)로 넘어가기 위한 **정리·전환용 릴리스**. 신기능보다 **정리/파괴적 변경**이 핵심.

- ⭐ **`strict: true`가 기본값** — 설정 안 하던 코드베이스는 갑자기 대량 에러 → 최대 마이그레이션 난관
- 최저 타깃이 **ES2015**로 상향, `target: es5` **폐기(deprecated)**
- **폐기 예정 옵션** (7.0에서 제거): `baseUrl`, `outFile`, `moduleResolution: node`(classic), `module`을 namespace처럼 쓰기, `assert` import 구문
- 완충 장치: `"ignoreDeprecations": "6.0"` 지정 시 폐기 옵션이 당장은 에러 없이 동작
- es2025 타깃/lib, Temporal API 타입, `Map.getOrInsert`, `#/` 서브패스 import, `--stableTypeOrdering`(6→7 마이그레이션 보조)

```jsonc
// tsconfig.json — 6.0에서 폐기 옵션 유예받기
{ "compilerOptions": { "ignoreDeprecations": "6.0" } }
```

## TypeScript 7.0 (2026.07.08 GA) — 네이티브(Go) 컴파일러 ⭐

- **"Project Corsa"** — 컴파일러/언어 서비스를 **Go로 전면 재작성** (동작·타입 검사 결과는 기존과 동일하게 유지)
- **~10배 빠름** (풀 빌드 8~12x). 예: VS Code 코드베이스 타입 검사 125.7초 → 10.6초 (약 11.9x)
- 파싱·타입 검사·emit을 **병렬화**
- 새 플래그: `--checkers`(검사 워커 수), `--builders`(프로젝트 참조 병렬 빌드), `--singleThreaded`
- `tsc` 바이너리 자체가 이제 Go 네이티브 (별도 `tsgo` 이름은 nightly `@typescript/native-preview`에만 남음)
- 6.0에서 폐기됐던 옵션들 **완전 제거**
- 주의: 안정적인 **프로그래밍 API는 7.1 이후** 제공 예정

```bash
npm install -D typescript@7   # tsc 가 Go 네이티브 컴파일러
tsc --singleThreaded          # 필요 시 단일 스레드 강제
```

## 면접 대비 메모 (Q/A)

- Q: `satisfies`와 타입 애노테이션(`: Type`)의 차이는?
  A: `: Type`은 값을 그 타입으로 **넓혀서** 취급(리터럴 정보 손실). `satisfies`는 타입 **검사만** 하고 실제 추론된 좁은 타입을 그대로 유지. (4.9)

- Q: `as`(타입 단언)와 `satisfies`의 차이는?
  A: `as`는 검사 없이 "믿어달라"고 강제(위험). `satisfies`는 실제로 타입에 맞는지 **검사**함. 되도록 `as`보다 `satisfies`.

- Q: `type` import 수식어(`import { type A }`)는 왜 쓰나?
  A: 타입 전용 import임을 명시 → 번들러가 런타임에서 제거(트리 셰이킹), `--verbatimModuleSyntax`와 궁합. (4.5)

- Q: `using` 선언은 무엇을 해결하나?
  A: 파일/커넥션/락 등 리소스를 스코프 종료 시 **자동 정리**(`Symbol.dispose`). try/finally 보일러플레이트 제거. (5.2)

- Q: `--erasableSyntaxOnly`가 나온 배경은?
  A: Node.js가 타입만 지우고 `.ts`를 바로 실행하는 흐름(빌드리스). enum/namespace 등 **런타임 코드를 생성하는 TS 문법**을 금지해 "지우기만 하면 되는" 코드로 강제. (5.8)

- Q: enum 대신 무엇을 쓰면 좋나?
  A: `as const` 객체 + 유니온 타입. 런타임 코드가 안 생겨 erasable하고 트리 셰이킹에 유리. `const obj = { A: 'a' } as const; type T = typeof obj[keyof typeof obj];`

- Q: TS 7.0이 빠른 이유는?
  A: 컴파일러를 JS→**Go로 재작성**하고 파싱·검사·emit을 **병렬화**. 타입 검사 로직 자체는 동일하게 이식(결과 호환). (7.0)

- Q: 6.0으로 올릴 때 가장 큰 이슈는?
  A: `strict`가 **기본 true**로 바뀌어 기존 느슨한 코드에서 에러가 쏟아짐. `target: es5`도 폐기. 폐기 옵션은 `ignoreDeprecations: "6.0"`로 임시 유예 가능.
