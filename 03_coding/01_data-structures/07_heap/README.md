# 07. Heap (힙)

## 1. 힙이란?

**완전 이진 트리 기반의 우선순위 자료구조.**
부모-자식 간 대소 관계만 유지하고, 형제 간 순서는 신경 쓰지 않는다.

- **최소 힙(Min-Heap)**: 부모 ≤ 자식 → 루트가 최솟값
- **최대 힙(Max-Heap)**: 부모 ≥ 자식 → 루트가 최댓값

### 도식 — 최소 힙 vs 최대 힙

```
        Min-Heap                       Max-Heap
       (루트 = 최솟값)                 (루트 = 최댓값)

           [1]                            [40]
          /   \                          /    \
        [3]   [5]                      [30]   [25]
       /  \   / \                      /  \    / \
     [7] [9][8][6]                   [20][15][18][10]

    부모 ≤ 자식                       부모 ≥ 자식
```

> ⚠️ **형제끼리 순서는 무관**. `3 < 5`가 보장되지 않는다.
> 힙은 "정렬된 자료구조"가 아니라 "**루트만 보장**되는 자료구조".

핵심 연산 비용:

| 연산 | 시간복잡도 | 설명 |
|------|-----------|-----|
| `push(v)` | O(log n) | 말단에 추가 후 위로 swap |
| `pop()` | O(log n) | 루트 반환, 말단을 루트로 옮긴 뒤 아래로 swap |
| `peek()` | O(1) | 루트 조회만 |
| `build` | O(n) | 배열에서 한 번에 힙 만들기 (heapify) |

**왜 빠른가?** 트리 높이가 log n이라 swap이 그 깊이만큼만 일어남.

## 2. 배열로 구현하는 이유

완전 이진 트리는 빈자리가 없으므로 배열에 그대로 매핑된다.

### 도식 — 트리 ↔ 배열 매핑

```
       트리                              배열 (0-base)

         [10] ← 0                  ┌────┬────┬────┬────┬────┬────┬────┐
        /    \                     │ 10 │ 20 │ 15 │ 30 │ 25 │ 18 │ 40 │
      [20]   [15]                  └────┴────┴────┴────┴────┴────┴────┘
     ←1      ←2                      0    1    2    3    4    5    6
     / \    / \
   [30][25][18][40]
   ←3  ←4 ←5  ←6


   인덱스 i 에서:
       부모    = (i - 1) >> 1
       왼자식  = 2*i + 1
       오른자식 = 2*i + 2

   예: i=4 (값 25)
       부모   = (4-1)>>1 = 1   → 20  ✅
       왼자식  = 2*4+1   = 9   → 없음
       오른자식 = 2*4+2   = 10  → 없음
```

포인터 기반 트리보다 캐시 친화적이고 메모리도 적게 든다.

### 도식 — `push` (Sift Up, 위로 올리기)

새 원소는 **항상 배열 끝**에 추가한 뒤, 부모와 비교하며 위로 올라간다.

```
   push(5) on Min-Heap:

   Step 1: 배열 끝에 추가         Step 2: 부모(20)와 비교 → swap

         [10]                            [10]
        /    \                          /    \
      [20]   [15]                     [5]   [15]
      / \    /                        / \    /
    [30][25][18]                    [30][25][18]
    /                               /
   [5]  ←새로 추가                [20]


   Step 3: 부모(10)와 비교 → swap   Step 4: 루트 도달, 종료

         [10]                            [5]
        /    \                          /   \
       [5]   [15]                    [10]   [15]
       / \    /                      / \    /
     [30][25][18]                  [30][25][18]
     /                              /
    [20]                          [20]

   비용: O(log n)  — 트리 높이만큼만 swap
```

### 도식 — `pop` (Sift Down, 아래로 내리기)

루트를 꺼내고, **마지막 원소를 루트 자리**로 옮긴 뒤 자식과 비교하며 내려간다.

```
   pop() on Min-Heap (루트 5 반환):

   Step 1: 루트 꺼냄, 마지막을 루트로

        [_]                           [20]  ← 마지막 원소 이동
       /   \                         /    \
     [10]   [15]                  [10]   [15]
     / \    /                     / \    /
   [30][25][18]                 [30][25][18]
   /
  [20]


   Step 2: 작은 자식(10)과 비교 → swap   Step 3: 작은 자식(25)과 비교 → swap

        [10]                              [10]
       /    \                            /    \
     [20]   [15]                      [25]   [15]
     / \    /                         / \    /
   [30][25][18]                    [30][20][18]

                                   ↑ 자기 자리, 종료

   비용: O(log n)
```

> 💡 핵심은 **항상 작은(또는 큰) 쪽 자식과 swap**.
> 그래야 부모 ≤ 양 자식 조건을 깨지 않는다.

## 3. "힙 문제"라고 신호 잡기

다음 키워드가 보이면 힙을 의심.

| 키워드                 | 힙 유형   |
| ------------------- | ------ |
| "K번째로 큰/작은"         | 크기 K 힙 |
| "Top K", "가장 ~한 K개" | 크기 K 힙 |
| "가장 작은/큰 것 반복 추출"   | 우선순위 큐 |
| "스케줄링", "작업 처리 순서"  | 우선순위 큐 |
| "중앙값을 실시간으로"        | 듀얼 힙   |
| "K개 정렬 리스트 병합"      | 크기 K 힙 |
| "최단 경로" (Dijkstra)  | 최소 힙   |

핵심 신호:
**"매번 최솟값/최댓값을 꺼내야 한다"** + **"꺼낸 뒤에도 새 값이 계속 들어온다"** → 힙.

> 정렬은 한 번 정렬 후 변하지 않는 데이터에만 유리.
> 힙은 **동적으로 들어오고 나가는** 상황에 강점.

## 4. 어떤 힙을 쓸지 선택

```
가장 큰 것을  빨리 꺼내야 한다     → 최대 힙
가장 작은 것을 빨리 꺼내야 한다   → 최소 힙
K번째로 큰 수                    → 크기 K짜리 최소 힙 (역설!)
K번째로 작은 수                  → 크기 K짜리 최대 힙
중앙값                           → 최대 힙(왼쪽) + 최소 힙(오른쪽)
```

### 역설 포인트 — "K번째 큰 수 = 최소 힙"

크기 K 힙에서 루트(최솟값)는
"지금까지 본 Top-K 중 가장 작은 값" = **K번째 큰 수**.

새 값이 루트보다 크면 → 루트 교체 (Top-K 후보)
새 값이 루트보다 작거나 같으면 → 무시

## 5. 4가지 대표 패턴

### 패턴 A — Top-K (크기 K 유지)

```
크기 K짜리 힙을 유지하며 배열 순회
→ 시간 O(n log k), 공간 O(k)
```

```
   nums = [3, 2, 1, 5, 6, 4],  k = 2
   목표: 2번째로 큰 수 = 5

   ┌─────┬───────────┬───────────────────────┐
   │ 값  │ Min-Heap  │ 동작                  │
   ├─────┼───────────┼───────────────────────┤
   │  3  │ [3]       │ push (크기 < k)       │
   │  2  │ [2, 3]    │ push (크기 < k)       │
   │  1  │ [2, 3]    │ 1 ≤ 2 → 무시          │
   │  5  │ [3, 5]    │ 5 > 2 → 2 pop, 5 push │
   │  6  │ [5, 6]    │ 6 > 3 → 3 pop, 6 push │
   │  4  │ [5, 6]    │ 4 ≤ 5 → 무시          │
   └─────┴───────────┴───────────────────────┘

   답 = heap.peek() = 5
   ┃
   ┗━ 루트(최솟값) = "Top-K 중 가장 작은 값" = K번째 큰 수
```

예: K번째 큰 수, K개 빈출 원소, 가장 가까운 K개 점

### 패턴 B — 반복 합성/소비

```
while (조건) {
  최솟값 두 개 pop → 합성 → push
}
```

```
   "더 맵게": scoville = [1, 2, 3, 9, 10, 12],  K = 7
   합성식: new = a + b * 2  (a ≤ b)

   초기 Min-Heap:    [1, 2, 3, 9, 10, 12]

   1회: pop 1, 2  → 1 + 2*2 = 5    push 5
        Heap: [3, 5, 9, 10, 12]

   2회: pop 3, 5  → 3 + 5*2 = 13   push 13
        Heap: [9, 10, 12, 13]            ← 루트(9) ≥ 7,  종료

   결과: 2회

         pop 두 개         push 한 개
       ┌──────────┐       ┌────────┐
       │  최솟값  │ ───→ │ 합성값 │
       └──────────┘       └────────┘
            ↑________________|
              루프 (루트 ≥ K 까지)
```

예: 더 맵게, Huffman 코딩, 돌 합치기

### 패턴 C — 듀얼 힙 (중앙값)

```
maxHeap: 왼쪽 절반 (최댓값이 루트)
minHeap: 오른쪽 절반 (최솟값이 루트)
크기 차이 ≤ 1 유지

중앙값:
  - 두 힙 크기 같음   → (maxHeap.top + minHeap.top) / 2
  - 한쪽이 1 더 큼    → 더 큰 쪽의 top
```

```
   stream: 5, 2, 8, 1, 9   →   중앙값을 매번 출력

           ┌─────── 중앙값 경계 ───────┐
           │                            │
           ▼                            ▼
      ┌──────────┐                ┌──────────┐
      │ Max-Heap │                │ Min-Heap │
      │  (왼쪽)  │                │ (오른쪽) │
      │ top=최대 │                │ top=최소 │
      └──────────┘                └──────────┘

   push 5:   max=[5]            min=[]           median = 5
   push 2:   max=[2]            min=[5]          median = (2+5)/2 = 3.5
   push 8:   max=[5,2]          min=[8]          median = 5
   push 1:   max=[2,1]          min=[5,8]        median = (2+5)/2 = 3.5
   push 9:   max=[5,2,1]        min=[8,9]        median = 5

   규칙:
     1) 새 값 ≤ max.top  → max.push,  아니면 min.push
     2) 크기 차이 > 1 이면 큰 쪽에서 pop → 반대편 push
```

예: 데이터 스트림 중앙값, 슬라이딩 윈도우 중앙값

### 패턴 D — K개 정렬 리스트 병합

```
각 리스트의 head를 힙에 넣음
pop → 결과에 추가 → 같은 리스트의 다음 원소 push
```

```
   L1: [1, 4, 7]     ──┐
   L2: [2, 5, 8]     ──┼──→  병합 결과: [1, 2, 3, 4, 5, 6, 7, 8, 9]
   L3: [3, 6, 9]     ──┘

   초기 힙 (각 리스트 head, [값, 리스트번호, 인덱스]):
       [ (1,L1,0), (2,L2,0), (3,L3,0) ]

   ┌──── 반복 ────┐
   │  pop 최솟값  │ → 결과에 추가
   │  같은 리스트  │
   │  다음 원소를  │
   │  힙에 push    │
   └───────────────┘

   step 1:  pop (1,L1,0)  → 결과=[1]   push (4,L1,1)
   step 2:  pop (2,L2,0)  → 결과=[1,2] push (5,L2,1)
   step 3:  pop (3,L3,0)  → ...
   ...

   힙 크기는 항상 K 이하  →  시간 O(N log K)
                            (N = 전체 원소 수)
```

예: K개 정렬 리스트 머지, K개 정렬 행렬에서 K번째 원소

## 6. JS 구현 템플릿

JS는 내장 힙이 없어 직접 구현해야 한다.

```js
class MinHeap {
  constructor() { this.h = []; }
  size() { return this.h.length; }
  peek() { return this.h[0]; }

  push(v) {
    this.h.push(v);
    this._up(this.h.length - 1);
  }

  pop() {
    const top = this.h[0];
    const last = this.h.pop();
    if (this.h.length) {
      this.h[0] = last;
      this._down(0);
    }
    return top;
  }

  _up(i) {
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.h[p] <= this.h[i]) break;
      [this.h[p], this.h[i]] = [this.h[i], this.h[p]];
      i = p;
    }
  }

  _down(i) {
    const n = this.h.length;
    while (true) {
      const l = i * 2 + 1, r = i * 2 + 2;
      let s = i;
      if (l < n && this.h[l] < this.h[s]) s = l;
      if (r < n && this.h[r] < this.h[s]) s = r;
      if (s === i) break;
      [this.h[s], this.h[i]] = [this.h[i], this.h[s]];
      i = s;
    }
  }
}
```

### Max-Heap 트릭

별도 구현 없이 `MinHeap`에 `-value`를 넣으면 끝.

```js
heap.push(-v);
const max = -heap.pop();
```

### 우선순위가 있는 객체 비교

`[priority, value]` 튜플로 넣고 비교 함수만 바꿔주거나,
힙 클래스에 `compare` 콜백을 받게 설계.

```js
class Heap {
  constructor(compare = (a, b) => a - b) {
    this.h = [];
    this.cmp = compare;
  }
  // _up, _down에서 this.cmp(a, b) < 0 로 비교
}
```

## 7. 풀기 전 자문 3가지

1. **K가 n에 비해 작은가?**
   작다면 정렬(O(n log n))보다 힙(O(n log k))이 유리.
2. **데이터가 동적으로 추가/제거되나?**
   Yes → 힙, No → 정렬도 충분.
3. **꺼낸 결과를 다시 변형해서 넣는가?**
   Yes → 힙(패턴 B), No → 정렬도 가능.

## 8. 자주 하는 실수

- **"K번째 큰 수니까 최대 힙"** → ❌ 최소 힙(크기 K)이 정석.
- **부모/자식 인덱스 공식 오타** → `(i-1)>>1`, `2i+1`, `2i+2` 외우기.
- **`pop` 후 빈 힙에서 `_down` 호출** → 크기 체크 필수.
- **객체 비교 시 `<` 그대로 사용** → JS는 객체 비교가 NaN. 키를 명시.
- **K개 정렬 리스트 머지에서 같은 값 중복 처리** → 인덱스도 함께 저장해 안정 정렬 유지.
