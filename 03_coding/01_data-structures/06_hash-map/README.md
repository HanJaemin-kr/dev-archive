# 06. Hash Map (해시 맵)

## 1. 해시 맵이란?

**키를 해시 함수로 변환해 배열 인덱스로 매핑하는 자료구조.**
키-값 쌍을 평균 O(1) 시간에 저장/조회한다.

### 도식 — 기본 동작

```
   put("apple", 3)

       "apple" ──hash()──→ 7   →  bucket[7] = ("apple", 3)

   get("apple")

       "apple" ──hash()──→ 7   →  bucket[7] 조회

      ┌────────────────────────────┐
      │ index │  bucket            │
      ├───────┼────────────────────┤
      │   0   │  ─                  │
      │   1   │  ("banana", 5)     │
      │   2   │  ─                  │
      │  ...  │  ...                │
      │   7   │  ("apple", 3)      │
      │  ...  │  ...                │
      └────────────────────────────┘
```

## 2. 시간복잡도

| 연산 | 평균 | 최악 |
|------|------|------|
| `put` / `set` | O(1) | O(n) (모두 같은 버킷일 때) |
| `get` | O(1) | O(n) |
| `delete` | O(1) | O(n) |
| `has` | O(1) | O(n) |

> 최악이 O(n)이지만 잘 설계된 해시 함수 + 자동 리사이즈로 실무에서는 O(1)로 봐도 무방.

## 3. 해시 충돌과 해결

같은 인덱스에 여러 키가 매핑되는 것이 **충돌(collision)**.

### 체이닝 (Chaining)

```
   bucket[7] ─→ ("apple", 3) ─→ ("apricot", 9) ─→ null

   같은 버킷에 연결 리스트로 매달기.
   JS의 Map 내부 구현에서도 사용.
```

### 개방 주소법 (Open Addressing)

```
   충돌 시 다음 빈 칸으로 이동 (선형/이차/이중 해싱).

   index:  5   6   7   8   9
          [ ][ ][a][b][ ]
                  ↑ 충돌 → 다음 칸 8로 이동
```

## 4. JS의 해시 자료구조

### `Object` vs `Map`

| 항목 | `Object {}` | `Map` |
|------|-------------|-------|
| 키 타입 | 문자열/심볼만 | **모든 값** (객체도 가능) |
| 순회 순서 | 삽입순 보장 (대부분) | 삽입순 **보장** |
| 크기 | `Object.keys(o).length` (O(n)) | `m.size` (O(1)) |
| 성능 | 일반적으로 느림 | 빠름 |
| 프로토타입 충돌 | `__proto__` 등 위험 | 없음 |

> **코딩 테스트에서는 `Map`을 기본으로**. 객체 키, 빈도 카운트, 큰 데이터 모두 안전.

```js
const m = new Map();
m.set('apple', 3);
m.get('apple');       // 3
m.has('apple');       // true
m.delete('apple');
m.size;
for (const [k, v] of m) { ... }
```

### `Set`

값만 저장하는 해시 집합.

```js
const s = new Set([1, 2, 3]);
s.add(4);
s.has(2);     // true
s.delete(1);
s.size;
```

## 5. 대표 패턴

### 패턴 A — 빈도 카운트

```
   "문자열 빈도 세기"   s = "aabbcccc"

   map: {}
   for ch in s:
     map[ch] = (map[ch] ?? 0) + 1

   결과: { a:2, b:2, c:4 }

   ┌───┬───┐
   │ a │ 2 │
   │ b │ 2 │
   │ c │ 4 │
   └───┴───┘

   → 애너그램 비교, 가장 많이 나온 원소, 빈출 K개 등
```

### 패턴 B — 보수(Complement) 탐색

```
   "두 수의 합" — nums에서 두 수를 더해 target = 9가 되는 인덱스?

   nums = [2, 7, 11, 15],  target = 9

   i=0, v=2:   필요한 보수 = 9-2 = 7
              map에 7 없음 → map = { 2: 0 }

   i=1, v=7:   필요한 보수 = 9-7 = 2
              map에 2 있음! → 답 = [0, 1]

   ───────────────────────────────────────
   한 번의 O(n) 순회로 끝. 정렬 + 투포인터의 O(n log n) 대체.
```

### 패턴 C — 그룹핑 (애너그램)

```
   "애너그램끼리 묶기"  ["eat", "tea", "tan", "ate", "nat", "bat"]

   각 단어를 정렬한 문자열을 키로 사용:

       "eat" → "aet"   ┐
       "tea" → "aet"   ├─→ ["eat", "tea", "ate"]
       "ate" → "aet"   ┘

       "tan" → "ant"   ┐
       "nat" → "ant"   ├─→ ["tan", "nat"]

       "bat" → "abt"   ─→ ["bat"]
```

### 패턴 D — 등장 여부 / 집합 연산 (Set)

```
   "최장 연속 수열"  nums = [100, 4, 200, 1, 3, 2]

   1) Set으로 변환:  {100, 4, 200, 1, 3, 2}

   2) 각 수에 대해 "이 수가 수열의 시작인가?" 확인
      (= num-1이 Set에 없으면 시작)

      100: 99 없음 → 시작.  100, 101?... → 길이 1
        4: 3 있음 → 시작 X
      200: 199 없음 → 시작.  200, 201?... → 길이 1
        1: 0 없음 → 시작.  1, 2, 3, 4, 5? → 길이 4 ✅
      ...

   최장 = 4

   비용: O(n) — 각 수는 두 번 이상 방문되지 않음.
```

### 패턴 E — 누적 합 + 해시 (부분합)

```
   "합이 K인 부분 배열 개수"

   누적합 S[i] 를 만들고, S[j] - S[i] = K  ⇔  S[i] = S[j] - K.

   map: 누적합 → 등장 횟수
   순회하며 (현재누적 - K)가 map에 몇 번 나왔는지 누적.

   nums = [1, 1, 1], K = 2
   누적: 0, 1, 2, 3
   확인:    0    1   2  → 답: 2 (인덱스 [0..1], [1..2])
```

## 6. 자주 하는 실수

- **객체 키 사용 시 자동 문자열화**
  ```js
  const o = {};
  o[1] = 'a';  o['1'] = 'b';   // 같은 키. o[1] = 'b'
  ```
  → 숫자/배열/객체 키는 `Map` 사용.
- **객체의 `in` vs `hasOwnProperty`** → 프로토타입 체인까지 확인됨. 안전하려면 `Object.hasOwn(o, k)`.
- **`Map`인데 `o[k]`로 접근** → `undefined`. `map.get(k)`.
- **`Set` 안의 객체 중복 판별** → 참조 비교. 내용 같아도 다른 객체면 별개.
- **해시 키로 `JSON.stringify`** → 키 순서 다르면 다른 문자열. 정렬 후 사용.

## 8. 한 줄 요약

> **"O(n²) → O(n) 로 줄일 때 가장 먼저 떠올리는 도구."**
>
> 빈도 카운트 / 보수 탐색 / 그룹핑 / Set 등장 여부 — 4가지 패턴만 알면 80% 해결.
> JS에서는 **무조건 `Map`/`Set`** 부터 떠올릴 것.
