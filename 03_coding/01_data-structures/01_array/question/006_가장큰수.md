# 006. 가장 큰 수

- **유형**: 정렬
- **출처**: 프로그래머스 Lv.2
- **날짜**: 2026-05-17
- **소요 시간**: 분
- **결과**: ✅

---

## 문제 설명

숫자 배열이 주어질 때, 숫자들을 이어붙여 만들 수 있는 가장 큰 수를 문자열로 반환하라.

## 제한사항

| 항목 | 값 |
|------|-----|
| numbers 길이 | 1 이상 100,000 이하 |
| numbers 원소 | 0 이상 1,000 이하 |

---

## 알고리즘 선택 분석

숫자 자체 크기가 아니라 **이어붙였을 때의 크기**를 기준으로 정렬해야 한다.

```text
3 vs 30 → "330" vs "303" → 330이 크므로 3이 앞
```

두 수 `a`, `b`를 비교할 때 `b+a`와 `a+b`를 숫자로 비교하면 최적 순서를 결정할 수 있다.  
인접한 모든 쌍이 최적이면 전체 순서도 최적 → 정렬 기준 설계로 해결.

---

## 내 풀이

```js
function solution(numbers) {
  const answer = numbers
    .map(String)
    .sort((a, b) => (b + a) - (a + b))
    .join('');

  return answer[0] === '0' ? '0' : answer;
}
```

## 복잡도

- 시간: O(n log n) — 정렬
- 공간: O(n) — 문자열 변환 배열

---

## 핵심 포인트

### sort 기준 설계

숫자 정렬이 아니라 **"붙였을 때 누가 앞에 오면 더 큰가"** 를 정의한다.

```js
sort((a, b) => (b + a) - (a + b))
```

| a | b | b+a | a+b | 결과 | 배치 |
|---|---|-----|-----|------|------|
| "3" | "30" | "303" | "330" | 303-330 = -27 (음수) | a(3) 앞 |
| "9" | "5" | "59" | "95" | 59-95 = -36 (음수) | a(9) 앞 ❌ → b(5) 앞 |

> `sort((a,b)=>...)` 에서 음수면 a 앞, 양수면 b 앞.

### sort 반환값 정리

| 반환값 | 의미 |
|--------|------|
| 음수 | a를 앞에 |
| 양수 | b를 앞에 |
| 0 | 그대로 |

### sort 기준 모음

| 문제 | 기준 |
|------|------|
| 숫자 오름차순 | `a - b` |
| 숫자 내림차순 | `b - a` |
| 문자열 길이 | `a.length - b.length` |
| 가장 큰 수 | `(b+a) - (a+b)` |
| 객체 정렬 | `a.age - b.age` |

---

## 막혔던 점 / 오답 노트

### `[0, 0, 0]` 예외 처리

정렬 후 join하면 `"000"`이 나오지만 정답은 `"0"`.  
첫 글자가 `'0'`이면 전체가 0이므로 `'0'` 반환.

```js
return answer[0] === '0' ? '0' : answer;
```

### sort 기본 함정

```js
[1, 10, 2].sort() // → [1, 10, 2]
```

기본 `sort()`는 유니코드(문자열) 기준 정렬 → `"1" < "10" < "2"` 사전순.  
숫자 정렬은 반드시 비교 함수 전달.

### 왜 모든 쌍을 직접 비교하지 않아도 되나?

정렬은 인접한 두 원소의 최적 순서를 반복적으로 맞추는 과정이다.  
`a+b > b+a`이면 a가 앞에 오는 게 항상 이득이므로, 인접 비교만으로 전체 최적 순서가 보장된다.
