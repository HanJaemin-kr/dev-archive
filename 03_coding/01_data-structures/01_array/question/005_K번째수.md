# 005. K번째 수

- **유형**: 정렬
- **출처**: 프로그래머스 Lv.1
- **날짜**: 2026-05-17
- **소요 시간**: 분
- **결과**: ✅

---

## 문제 설명

배열 `array`와 명령어 배열 `commands`가 주어진다.  
각 명령어 `[i, j, k]`에 대해 `array`의 i번째부터 j번째 요소를 자른 후 정렬하여 k번째 수를 구하라.

## 제한사항

| 항목 | 값 |
|------|-----|
| array 길이 | 1 이상 100 이하 |
| array 원소 | 1 이상 100 이하 |
| commands 길이 | 1 이상 50 이하 |
| i ≤ j, k ≤ j - i + 1 | 항상 유효한 범위 보장 |

---

## 알고리즘 선택 분석

입력 크기가 최대 100으로 작아 O(n² log n) 브루트포스도 충분하다.  
`slice → sort → index` 3단계로 해결 가능.

---

## 내 풀이

```js
function solution(array, commands) {
  var answer = [];
  commands.forEach(commandRow => {
    var sortedParse = array.slice(commandRow[0] - 1, commandRow[1])
                          .sort((a, b) => a - b);
    answer.push(sortedParse[commandRow[2] - 1]);
  });
  return answer;
}
```

## 복잡도

- 시간: O(m × n log n) — m: commands 길이, n: slice 구간 길이
- 공간: O(n) — 잘라낸 부분 배열

## 핵심 포인트

- `slice(i-1, j)` — 문제의 i, j는 1-indexed이므로 시작은 `-1`, 끝은 그대로 (slice end는 미포함)
- `sort((a, b) => a - b)` — 숫자 정렬은 비교 함수 필수 (없으면 유니코드 기준)
- `sortedParse[k-1]` — k도 1-indexed이므로 `-1`

## 막혔던 점 / 오답 노트

### `forEach` 대신 `map`을 써야 하는 이유

`forEach`는 반환값이 없어 결과를 외부 배열에 `push`해야 한다.  
`map`은 각 요소의 반환값으로 새 배열을 자동 생성하므로 코드가 간결하고 의도가 명확하다.

| | `forEach` + `push` | `map` |
|---|---|---|
| 반환값 | `undefined` | 새 배열 |
| 외부 변수 필요 | ✅ `answer = []` 선언 필요 | ❌ 불필요 |
| 의도 표현 | "순회하면서 뭔가 한다" | "변환된 새 배열을 만든다" |

```js
// forEach 방식 — 외부 answer 배열이 필요
function solution(array, commands) {
  var answer = [];
  commands.forEach(commandRow => {
    var sortedParse = array.slice(commandRow[0] - 1, commandRow[1])
                          .sort((a, b) => a - b);
    answer.push(sortedParse[commandRow[2] - 1]);
  });
  return answer;
}

// map 방식 — 더 선언적, answer 변수 불필요
function solution(array, commands) {
  return commands.map(([i, j, k]) =>
    array.slice(i - 1, j).sort((a, b) => a - b)[k - 1]
  );
}
```

> 결과를 새 배열로 모아야 할 때는 `map`이 정답.  
> `forEach`는 콘솔 출력, 상태 변경 등 **부작용**이 목적일 때 사용한다.
