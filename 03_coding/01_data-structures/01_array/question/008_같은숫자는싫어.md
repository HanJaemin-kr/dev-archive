# 008. 같은 숫자는 싫어

- **유형**: 배열 / 스택
- **날짜**: 2026-05-19
- **출처**: 프로그래머스 Lv.1
- **결과**: 통과

---

## 문제 설명

숫자로 이루어진 배열 `arr`에서 **연속으로 나타나는 중복 숫자를 제거**하여 반환하라.  
순서는 유지하고, 연속되지 않은 같은 숫자는 제거하지 않는다.

**예시**

```
입력: [1, 1, 3, 3, 0, 1, 1]
출력: [1, 3, 0, 1]
```

---

## 내 풀이

```js
function solution(arr) {
  const END = Symbol();
  const parseArr = [...arr, END];
  const answer = [];
  for (let i = 1; i < parseArr.length; i++) {
    const cur = parseArr[i - 1];
    const next = parseArr[i];
    if (cur !== next) {
      answer.push(cur);
    }
  }
  return answer;
}
```

**아이디어**: 배열 끝에 `Symbol()` sentinel을 붙여 마지막 원소도 동일한 로직으로 처리.  
`cur != next` 이면 `cur`를 결과에 추가. 마지막 원소는 `END`와 항상 다르므로 자동으로 포함됨.

## 복잡도

- 시간: O(n)
- 공간: O(n)

---

## 효율적 풀이 — `filter` 한 줄

```js
function solution(arr) {
  return arr.filter((v, i) => v !== arr[i + 1]);
}
```

**아이디어**: `arr[i + 1]`이 `undefined`인 마지막 원소는 `v !== undefined`가 항상 `true`이므로
sentinel 없이도 자동으로 포함된다.

| 항목 | 내 풀이 | filter 풀이 |
|------|---------|-------------|
| 시간복잡도 | O(n) | O(n) |
| 공간복잡도 | O(n) | O(n) |
| 코드 길이 | 길다 | 1줄 |
| sentinel 필요 | Symbol() | 불필요 |

---

## Symbol vs Infinity — sentinel 선택 이유

### `Infinity`를 쓰면 안 되는 경우

```js
const parseArr = [...arr, Infinity];
```

- `Infinity`는 **숫자 타입**이므로 배열 원소가 숫자라면 충돌 가능성이 있다.
- `arr = [1, 2, Infinity]` 처럼 실제 원소로 `Infinity`가 오면 sentinel 역할을 못 한다.
- 또한 아주 큰 수(`Number.MAX_SAFE_INTEGER` 등)를 sentinel로 쓰면,
  그 값이 입력에 포함될 경우 버그가 생긴다.

### `Symbol()`이 안전한 이유

```js
const END = Symbol();

END === END;          // true  (같은 참조)
END === Symbol();     // false (매번 새 고유값)
END === 0;            // false
END === Infinity;     // false
END === undefined;    // false
END === null;         // false
```

- `Symbol()`은 **세상에 단 하나인 고유값**을 생성한다.
- 어떤 숫자, 문자열, `null`, `undefined`와도 절대로 `===` 비교가 `true`가 되지 않는다.
- 따라서 배열 원소가 무엇이든 sentinel로 완벽하게 작동한다.

### 실전 요약

| sentinel | 안전한가? | 이유 |
|----------|----------|------|
| `Infinity` | 조건부 | 입력에 Infinity가 없을 때만 |
| `Number.MAX_SAFE_INTEGER` | 조건부 | 입력 범위 제한 시만 |
| `null` / `undefined` | 위험 | 입력이 sparse 배열이면 충돌 |
| `Symbol()` | **항상 안전** | 타입 자체가 고유, 충돌 불가 |

> **결론**: 입력값 범위를 보장할 수 없다면 항상 `Symbol()`을 써라.  
> 단, `filter` 풀이처럼 `arr[i+1] === undefined` 성질을 활용하면 sentinel 자체가 필요 없다.

---

## 막혔던 점 / 오답 노트

- 처음에 `Infinity`를 sentinel로 시도했으나 입력 범위 조건이 불명확할 경우 위험함을 인지.
- `Symbol()`로 교체해 안전하게 처리. 이후 `filter` 방식이 더 간결한 정답임을 확인.
