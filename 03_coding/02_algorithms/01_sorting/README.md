# 01. Sorting (정렬)

## 1. 정렬이란?

**원소들을 특정 기준으로 순서대로 재배열하는 것.**
대부분의 알고리즘 문제는 "정렬 후 OOO" 패턴으로 풀린다. 정렬 자체보다 **어떤 기준으로 정렬할지** 가 핵심.

### 도식 — JS `sort()` 의 함정

```
   [10, 9, 2, 21].sort()
                 │
                 ▼
         문자열로 변환 후 사전식 정렬
                 │
                 ▼
         "10" < "2" < "21" < "9"  → [10, 2, 21, 9]  ← 버그!

   숫자 정렬은 반드시 비교 함수 명시:
       [10, 9, 2, 21].sort((a, b) => a - b);  // [2, 9, 10, 21]
```

> JS `sort()` 는 기본이 **문자열 정렬**. 숫자/객체는 무조건 비교 함수를 직접 넘긴다.

## 2. 정렬 알고리즘 비교

| 알고리즘 | 평균 | 최악 | 최선 | 공간 | 안정 | 특징 |
|----------|------|------|------|------|------|------|
| 버블 | O(n²) | O(n²) | O(n) | O(1) | ✅ | 구현 단순. 조기 종료로 최선 O(n). 실전 거의 없음 |
| 선택 | O(n²) | O(n²) | O(n²) | O(1) | ❌ | swap 횟수 최소(n-1). 최선/최악 동일 |
| 삽입 | O(n²) | O(n²) | O(n) | O(1) | ✅ | 거의 정렬된 데이터에 매우 빠름 |
| 병합 | O(n log n) | O(n log n) | O(n log n) | O(n) | ✅ | 항상 보장. 연결 리스트 정렬에 최적 |
| 퀵 | O(n log n) | O(n²) | O(n log n) | O(log n) | ❌ | 평균 가장 빠름. 캐시 효율 좋음 |
| 힙 | O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ | 추가 메모리 없이 O(n log n) 보장 |
| 계수 | O(n + k) | O(n + k) | O(n + k) | O(k) | ✅ | 비교 없음 → O(n log n) 하한 돌파 |

### 언제 어떤 정렬을 쓰나

| 상황 | 선택 |
|------|------|
| 범위 고정 정수 (`-10만 ~ 10만`) | 계수 정렬 |
| 안정 정렬 필요 (동점자 순위 유지) | 병합 정렬 |
| 추가 메모리 없이 O(n log n) 보장 | 힙 정렬 |
| 일반 라이브러리 정렬 | 퀵 (V8은 TimSort) |
| 거의 정렬된 소규모 데이터 | 삽입 정렬 |
| n ≤ 1000 이고 구현 우선 | 선택/삽입 |

## 3. JS 정렬 템플릿

```js
// 숫자 오름차순 / 내림차순
nums.sort((a, b) => a - b);
nums.sort((a, b) => b - a);

// 문자열 (로케일 반영)
strs.sort((a, b) => a.localeCompare(b));

// 객체 — 여러 키로 정렬 (tie-breaker)
people.sort((a, b) => a.age - b.age || a.name.localeCompare(b.name));

// 원본 보존하며 정렬
const sorted = [...nums].sort((a, b) => a - b);
```

> ⚠️ `sort()` 는 **in-place** — 원본이 바뀐다. 보존하려면 `[...arr]` 또는 `arr.slice()` 후 정렬.

### 계수 정렬

```js
function countingSort(arr, min, max) {
  const count = new Array(max - min + 1).fill(0);
  for (const v of arr) count[v - min]++;
  const result = [];
  for (let i = 0; i < count.length; i++) {
    while (count[i]-- > 0) result.push(i + min);
  }
  return result;
}
```

## 4. 대표 패턴

### 패턴 A — 커스텀 비교자

```
   비교 함수 (a, b) => number
       음수 → a가 앞
       양수 → b가 앞
       0   → 동등 (안정 정렬에서 원래 순서 유지)
```

```js
// 객체 배열: 나이 오름차순, 동률이면 이름 사전순
arr.sort((a, b) => a.age - b.age || a.name.localeCompare(b.name));

// 절댓값 기준
arr.sort((a, b) => Math.abs(a) - Math.abs(b));
```

용도: 다중 키 정렬, 객체 정렬

### 패턴 B — 구간/좌표 정렬 후 그리디

```
   회의 [시작,종료] 가 여러 개 → 최대 회의 수?

   종료 시간 기준 정렬:
       [(1,4), (3,5), (0,6), (5,7), (3,8), ...]

   가장 빨리 끝나는 회의를 먼저 선택 → 남은 시간 최대화

   end = 0
   for (s, e) in sorted:
     if s >= end:
       count++
       end = e
```

용도: 구간 스케줄링, 강의실 배정, 활동 선택

### 패턴 C — 문자열 이어붙임 비교

```
   [6, 10, 2] 로 만들 수 있는 가장 큰 수는?

   비교 기준: a+b vs b+a (이어붙인 문자열)

       "6"+"10" = "610"
       "10"+"6" = "106"
       "610" > "106"  → 6이 앞

   nums.map(String).sort((a, b) => (b+a).localeCompare(a+b)).join('')
```

용도: 문자열 조합 최댓값/최솟값

### 패턴 D — 내림차순 + 인덱스 비교 (H-Index)

```
   citations = [3, 0, 6, 1, 5]
   내림차순:    [6, 5, 3, 1, 0]
   인덱스:       0  1  2  3  4

   citations[i] >= i+1 인 가장 큰 i+1 = H-Index

       i=0: 6 >= 1 ✅  h=1
       i=1: 5 >= 2 ✅  h=2
       i=2: 3 >= 3 ✅  h=3
       i=3: 1 >= 4 ❌  중단
       → H-Index = 3
```

용도: 정렬 후 인덱스로 답 추출

### 패턴 E — 계수 정렬 (값 범위 좁을 때)

```
   값 범위 k 가 n 과 비슷하거나 작을 때, O(n+k) 로 비교 없이 정렬.
   비교 정렬의 O(n log n) 하한을 돌파한다.

   예: 학생 점수 0~100, n=10^7 → counting sort 압도적
```

용도: 정수 범위 좁음, 안정 정렬 + O(n)

## 5. 자주 하는 실수

- **`[10, 2].sort()` 그대로 사용** → 문자열 정렬 됨. 숫자는 항상 `(a,b)=>a-b`.
- **`localeCompare` 없이 문자열 비교** → 한글/유니코드 순서 깨짐. 다국어는 `localeCompare`.
- **`sort()` 가 in-place 임을 잊음** → 원본 보존 필요하면 `[...arr].sort()`.
- **안정 정렬이라고 가정한 채 동점자 처리 누락** → V8 `sort()` 는 안정이지만, 명시적 tie-breaker 두는 게 안전.
- **`sort` 후 원본 인덱스 정보 잃어버림** → 필요하면 `[value, idx]` 튜플로 정렬.
- **`numbers.map(String).sort()` 후 `.join('')` 했는데 `"000..."` 처리 누락** → 모두 0이면 `"0"` 반환.

## 7. 한 줄 요약

> **"비교 함수 하나로 거의 다 끝낸다."**
>
> "어떻게 정렬?" 보다 "**어떤 기준으로?**" 가 본질.
> 구간 문제는 종료 시간, 객체는 다중 키, 숫자는 `(a,b)=>a-b` — 이 세 가지가 80%.
