# LLM 하네스(Harness)란?

## 1. 정의

**하네스(Harness)** 는 원래 "마구(馬具)" 를 뜻한다. 말에 안장과 고삐를 채워서 사람이 통제할 수 있게 만드는 장치다.

소프트웨어에서 하네스는 **"날것의 시스템(LLM, 테스트 대상, 외부 API 등)을 안전하고 일관되게 다루기 위해 감싸는 코드 계층"** 을 의미한다.

> LLM 하네스 = LLM 모델 + 신뢰성·관찰성·확장성을 위한 래퍼(Wrapper) 계층

---

## 2. 왜 필요한가?

LLM API를 직접 호출하는 코드는 다음과 같이 단순하다:

```python
import requests
response = requests.post("http://llm-server/v1/chat/completions",
                         json={"messages": [...]})
print(response.json()["choices"][0]["message"]["content"])
```

**이렇게만 짜면 생기는 문제들:**

| 문제         | 결과                      |
| ---------- | ----------------------- |
| 네트워크 일시 장애 | 실패 → 사용자 경험 악화          |
| 모델 서버 변경   | 모든 호출 코드를 일일이 수정        |
| 비용 추적 불가   | 토큰 사용량 모니터링 불가          |
| 로그 부재      | 장애 발생 시 원인 추적 불가        |
| 프롬프트 산재    | 같은 프롬프트가 여러 곳에 복붙됨      |
| 보안 키 노출    | 코드에 API 키 하드코딩          |
| 단일 호출만 가능  | 다단계 추론(CoT, RAG) 구현 어려움 |
|            |                         |

이런 문제들을 한 군데서 해결하는 게 **하네스의 존재 이유**다.

## 3. 하네스의 핵심 책임

```
┌────────────────────────────────────────────┐
│           Application Layer                │
│     (챗봇, RAG, 에이전트, API 서비스)       │
└────────────────┬───────────────────────────┘
                 │
                 ▼
┌────────────────────────────────────────────┐
│            LLM Harness                     │
│  ┌──────────┬──────────┬──────────────┐   │
│  │  Config  │  Client  │  Prompt      │   │
│  ├──────────┼──────────┼──────────────┤   │
│  │  Logger  │ Pipeline │  Cache/Eval  │   │
│  └──────────┴──────────┴──────────────┘   │
└────────────────┬───────────────────────────┘
                 │
                 ▼
┌────────────────────────────────────────────┐
│     LLM Backend (Qwen, GPT, Claude...)     │
└────────────────────────────────────────────┘
```

**6가지 핵심 책임:**

1. **추상화(Abstraction)** — 백엔드(Qwen/GPT/Claude)를 바꿔도 앱 코드는 그대로
2. **신뢰성(Reliability)** — 재시도, 타임아웃, 서킷 브레이커
3. **관찰성(Observability)** — 로깅, 메트릭, 트레이싱
4. **재사용성(Reusability)** — 프롬프트 템플릿, 파이프라인
5. **안전성(Safety)** — 키 관리, 입력 검증, 출력 필터링
6. **확장성(Scalability)** — 캐싱, 배칭, 비동기 처리

---

## 4. 하네스 vs SDK vs Framework

용어가 혼동되기 쉽다.

| 구분 | 예시 | 특징 |
|------|------|------|
| **SDK** | `openai` 패키지 | 벤더 제공, API 호출 수단만 제공 |
| **Harness** | 우리가 만든 `harness/` | 회사/프로젝트 맞춤 래퍼, SDK 위에 얹힘 |
| **Framework** | LangChain, LlamaIndex | 범용 프레임워크, 무겁고 의존성 많음 |

**기업에서 하네스가 선호되는 이유:**
- LangChain은 추상화가 과하고 디버깅이 어렵다
- 회사 내부 정책(로깅 포맷, 인증 방식, 모델 라우팅 규칙)을 강제할 수 있다
- 의존성이 가벼워 운영 부담이 적다
