# Remote-Control 팀 에이전트 개념

## 기존 방식의 한계

보통 AI 어시스턴트를 이렇게 쓴다.

```
[개발자] → [AI 챗봇] → [응답]
```

문제는 세 가지다.

- **단일 컨텍스트** — 설계, 구현, 리뷰를 한 창에서 하면 컨텍스트가 뒤섞인다
- **순차 처리** — 리서치 끝 → 설계 시작 → 구현 시작. 병렬 불가
- **디바이스 종속** — 터미널 닫으면 세션도 끊긴다

---

## 해결책: 3가지 기술의 결합

### 1. TMUX — 에이전트를 위한 물리적 공간

하나의 터미널에 여러 파인(Pane)을 만들고, 각 파인에서 Claude Code를 따로 실행한다.
→ 역할이 분리된 여러 AI가 동시에 작동한다.

```
┌──────────────┬──────────────┬──────────────┐
│  Pane 0      │  Pane 1      │  Pane 2      │
│  팀장 (쭌)   │  PM (민준)   │  리서쳐(지훈)│
│  claude      │  claude      │  claude      │
├──────────────┼──────────────┼──────────────┤
│  Pane 3      │  Pane 4      │  Pane 5      │
│  디자이너    │  개발자(서연)│  리뷰어(태양)│
│  claude      │  claude      │  claude      │
└──────────────┴──────────────┴──────────────┘
```

### 2. CLAUDE.md — 역할 정의

각 에이전트가 시작할 디렉토리에 `CLAUDE.md`를 두면 그 에이전트의 역할과 규칙이 정해진다.

```markdown
# 서연 (개발자)
## 역할
- 코드 구현, 테스트 작성
- 팀장의 지시에 따라 작업

## 규칙
- 직접 판단으로 아키텍처 변경 금지
- 구현 완료 시 팀장에게 보고
```

### 3. Remote-Control — 어디서든 지휘

로컬에서 돌고 있는 팀장 세션을 웹(`claude.ai/code`) 또는 모바일 앱으로 제어할 수 있다.
세션은 항상 **로컬에서 실행**되므로 로컬 파일시스템과 모든 도구를 그대로 사용한다.

```bash
claude --remote-control "팀 에이전트"
```

연결 구조:

```
[모바일 / 웹]
      │ TLS 암호화
      ▼
[Anthropic API 서버]  ← 라우팅만 담당, 실행 X
      │
      ▼
[로컬 머신 — TMUX 세션]  ← 실제 실행 위치
```

- 인바운드 포트 개방 불필요 (아웃바운드 연결만 사용)
- 네트워크 끊겨도 10분 내 복구 시 자동 재연결

## 아키텍처 레이어

```
┌─────────────────────────────────────┐
│  1. 제어 레이어 (Control Layer)     │
│     claude.ai/code, 모바일 앱       │
└────────────────┬────────────────────┘
                 │ Remote-Control
┌────────────────▼────────────────────┐
│  2. 오케스트레이션 레이어           │
│     팀장 (Pane 0)                   │
│     - 지시 수령 → 작업 분해 → 분배  │
└────────────────┬────────────────────┘
                 │ tmux send-keys
┌────────────────▼────────────────────┐
│  3. 실행 레이어 (Pane 1~5)          │
│     PM / 리서쳐 / 디자이너          │
│     개발자 / 리뷰어                 │
└────────────────┬────────────────────┘
                 │
┌────────────────▼────────────────────┐
│  4. 인프라 레이어                   │
│     파일시스템, Git, MCP 서버       │
└─────────────────────────────────────┘
```

**팀장의 역할**: 직접 코드를 쓰지 않는다. 지시 수령 → 작업 분해 → 팀원 배분 → 결과 종합 보고만 한다.

```bash
# 팀장이 팀원에게 지시 보내는 예시
tmux send-keys -t team:0.1 "결제 모듈 설계안 작성해줘" Enter   # PM
tmux send-keys -t team:0.4 "설계안 참고해서 구현 시작해" Enter  # 개발자
tmux send-keys -t team:0.5 "구현 끝나면 리뷰 부탁해" Enter     # 리뷰어
```

## 인간 팀 vs AI 팀 에이전트

| 항목 | 인간 팀 | AI 팀 에이전트 |
|------|---------|---------------|
| 가용 시간 | 업무 시간 | 24시간 |
| 역할 전환 | 채용·교육 필요 | CLAUDE.md 수정 |
| 동시 작업 | 인원 수 제한 | 파인 수만큼 |
| 커뮤니케이션 | 회의·슬랙 | tmux send-keys |
| 원격 지휘 | 메신저·이메일 | Remote-Control |

## 실제 시나리오 예시

> "출근길 지하철에서 모바일 앱으로 지시 → 사무실 도착 시 결과 확인"

1. 모바일에서 팀장에게: `"결제 모듈 리팩토링 시작해"`
2. 팀장이 작업 분해 → PM, 개발자, 리뷰어에게 각각 지시
3. PM이 설계 → 개발자가 구현 → 리뷰어가 검토 (병렬 진행)
4. 사무실 도착 → 터미널에서 진행 상황 확인, 필요 부분만 수정
