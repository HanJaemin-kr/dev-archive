Overview
OPC UA란?
산업 자동화에서 이기종 장비·시스템 간의 안전하고 신뢰할 수 있는 데이터 교환을 위한 국제 표준 (OPC Classic의 후계, 2006년~)

📦 표준화된 데이터 모델

설비 정보를 노드(Node)와 주소 공간(Address Space)으로 구조화. 공통 언어로 이기종 장비 연동.

🔒 보안 내장

TLS 암호화 + X.509 인증서 기반 인증·권한 관리가 프로토콜에 기본 내장. 별도 보안 구성 불필요.

🌐 플랫폼 독립

Windows·Linux·임베디드 MCU까지 동작. C/C++, Python, Java, .NET 등 다양한 SDK 제공.

📡 실시간 구독

Subscription + MonitoredItem으로 값 변경 시 자동 알림. Polling 없이 효율적인 데이터 수집.

🕰️ 이력 조회

Historical Access — 과거 데이터를 시간 범위로 직접 요청. 별도 DB 없이 서버에서 이력 제공 가능.

⚙️ 원격 제어

Method Call — 서버의 함수를 원격 실행. 펌프 Start/Stop, 설정값 변경 등 양방향 제어 가능.

OPC UA 아키텍처 — 클라이언트/서버 구조 위에 서비스·보안·전송 계층이 쌓임
OPC Classic vs OPC UA
OPC Classic은 Windows DCOM 기반으로 Windows에서만 동작. OPC UA는 플랫폼 독립적이며 보안·데이터 모델·실시간 구독이 하나의 표준으로 통합. 현재 모든 신규 산업 시스템은 OPC UA를 채택.

Communication
4가지 통신 방식
OPC UA는 단순 읽기부터 실시간 구독, 원격 제어까지 하나의 프로토콜로 지원합니다.
OPC UA 4가지 서비스 — 단순 읽기부터 실시간 구독, 원격 실행까지 단일 프로토콜로 지원
💡 Subscribe가 핵심 패턴
Read는 요청 시점의 값만 가져옴. Subscribe는 서버가 값 변경을 감지해 자동 통보 → Polling 부하 없이 실시간 데이터 수집 가능. 대부분의 실제 모니터링 시스템은 Subscribe 방식을 사용.
📡 Subscribe 핵심 패턴 (Python)
from asyncua import Client
from asyncua.common.subscription import SubHandler

class SensorHandler(SubHandler):
    def datachange_notification(self, node, val, data):
        ts = data.monitored_item.Value.SourceTimestamp
        print(f"[{ts}] {node} = {val}")   # 값 변경 시 자동 호출

async def main():
    async with Client("opc.tcp://plc:4840") as client:
        handler = SensorHandler()
        sub = await client.create_subscription(period=500, handler=handler)
        nodes = [client.get_node("ns=2;s=Line1.Pump01.VibrationRMS")]
        await sub.subscribe_data_change(nodes)
        await asyncio.sleep(float("inf"))   # 연결 유지

OPC UA는 3단계 보안 모드를 표준으로 정의. 개발 환경과 운영 환경에 따라 적절히 선택.

🔒 SignAndEncrypt 연결 (Python)
from asyncua.crypto.security_policies import SecurityPolicyBasic256Sha256
from asyncua import ua, Client

async def secure_connect():
    client = Client("opc.tcp://plc:4840")
    await client.set_security(
        SecurityPolicyBasic256Sha256,
        certificate="client_cert.pem",
        private_key="client_key.pem",
        server_certificate="server_cert.pem",
        mode=ua.MessageSecurityMode.SignAndEncrypt,
    )
    await client.connect()

🔗 OPC UA → MQTT 브리지 패턴
import asyncio, json
import paho.mqtt.client as mqtt
from asyncua import Client
from asyncua.common.subscription import SubHandler

NODE_TOPIC_MAP = {
    "ns=2;s=Line1.Pump01.VibrationRMS": "pdm/line1/pump/pump_01/vibration",
    "ns=2;s=Line1.Pump01.Temperature":  "pdm/line1/pump/pump_01/temperature",
    "ns=2;s=Line1.Motor03.RPM":         "pdm/line1/motor/motor_03/rpm",
}

class BridgeHandler(SubHandler):
    def __init__(self, mqtt_client):
        self.mqtt = mqtt_client

    def datachange_notification(self, node, val, data):
        topic = NODE_TOPIC_MAP.get(str(node.nodeid))
        if topic:
            payload = json.dumps({
                "value": val,
                "timestamp": data.monitored_item.Value.SourceTimestamp.isoformat(),
            })
            self.mqtt.publish(topic, payload, qos=1)

async def bridge():
    mc = mqtt.Client(); mc.connect("mosquitto", 1883); mc.loop_start()
    async with Client("opc.tcp://plc-line1:4840") as client:
        sub = await client.create_subscription(500, BridgeHandler(mc))
        await sub.subscribe_data_change([client.get_node(n) for n in NODE_TOPIC_MAP])
        await asyncio.sleep(float("inf"))

async def control_pump(client, pump_id, rpm):
    pump = client.get_node(f"ns=2;s=Line1.{pump_id}")

    # Start — 목표 RPM 전달
    result = await pump.call_method(
        "2:Start", rpm
    )
    print(f"Start result: {result}")

    # Stop
    await pump.call_method("2:Stop")

    # 쓰기 (설정값 변경)
    sp = client.get_node("ns=2;s=Pump01.SetpointRPM")
    await sp.write_value(1800)

from asyncua import ua
from datetime import datetime, timedelta, timezone

async def read_history(client):
    node  = client.get_node("ns=2;s=Pump01.VibrationRMS")
    end   = datetime.now(timezone.utc)
    start = end - timedelta(hours=1)

    history = await node.read_raw_history(
        starttime=start,
        endtime=end,
        numvalues=0,      # 0 = 제한 없음
    )
    for dv in history:
        print(f"{dv.SourceTimestamp}: {dv.Value.Value}")
🖥️ OPC UA 서버 구축
from asyncua import Server
import asyncio

async def run_server():
    server = Server()
    await server.init()
    server.set_endpoint("opc.tcp://0.0.0.0:4840/pdm/")
    ns     = await server.register_namespace("urn:pdm")
    objs   = server.get_objects_node()
    pump   = await objs.add_object(ns, "Pump01")
    rms    = await pump.add_variable(ns, "VibrationRMS", 0.0)
    await rms.set_writable()

    async with server:
        while True:
            await rms.write_value(read_sensor())  # 실센서 값 업데이트
            await asyncio.sleep(1)

async def connect_with_retry(url, max_retry=5):
    for i in range(max_retry):
        try:
            client = Client(url)
            await client.connect()
            return client
        except Exception as e:
            print(f"Retry {i+1}: {e}")
            await asyncio.sleep(2 ** i)   # 지수 백오프

Interview Q&A
면접·현장 핵심 Q&A
OPC UA와 MQTT의 가장 큰 차이는?
OPC UA는 구조화된 Address Space(정보 모델)를 제공하여 설비 데이터를 계층적으로 표현하고, 읽기·쓰기·구독·메서드 호출을 하나의 표준으로 지원. 보안도 프로토콜에 내장. MQTT는 토픽 기반 경량 발행-구독으로 자유도는 높지만 데이터 구조·보안을 개발자가 직접 설계해야 함. 현장 PLC가 OPC UA를 지원하면 OPC UA 직접 연결이 더 정확하고 표준적. 클라우드·경량 IoT는 MQTT.
Subscribe와 Read의 차이, 언제 무엇을 쓰나?
Read는 요청 시점의 값만 가져오는 단발성 조회. Subscribe는 서버가 값 변경을 감지해 자동 통보 — Polling 부하 없이 실시간 수집 가능. 실시간 모니터링·알람에는 Subscribe, 초기 설정값 확인·단순 조회에는 Read 사용.
OPC UA 서버가 내장되지 않은 레거시 장비를 연동하려면?
① Modbus·PROFIBUS 등 기존 프로토콜로 데이터를 읽어 Python OPC UA 서버로 래핑하는 Gateway 구축. ② 상용 OPC UA Gateway 장비(Prosys, Kepware 등) 사용. Python asyncua로 서버를 만들고 레거시 드라이버와 연결하면 표준 OPC UA 클라이언트가 연결 가능.
NodeId가 무엇이고 왜 중요한가?
OPC UA 주소 공간의 각 노드를 고유 식별하는 주소. Namespace Index(ns)와 식별자(숫자·문자열·GUID) 조합. 클라이언트는 NodeId로 정확한 노드를 지정해 읽기·쓰기·구독을 수행하므로 NodeId 파악이 연동의 첫 단계. UaExpert(무료 GUI 도구)나 browse 코드로 서버의 NodeId를 탐색해 매핑 테이블 작성.
OPC UA 보안 설정 시 최소 요구사항은?
운영 환경에서 반드시 SecurityMode.SignAndEncrypt + Basic256Sha256 이상 정책 적용. 클라이언트와 서버 각각 X.509 인증서 발급, 상호 인증서 교환 필요. None 모드는 개발·내부 테스트 전용. 인증서 자동 갱신 스크립트와 만료 모니터링도 필수.
Subscription의 PublishingInterval과 SamplingInterval 차이는?
SamplingInterval: 서버가 노드 값을 얼마나 자주 샘플링할지 (ms 단위). PublishingInterval: 샘플링된 변경 내용을 클라이언트에게 얼마나 자주 전송할지. SamplingInterval ≤ PublishingInterval이어야 함. 예: Sampling=100ms, Publishing=1000ms → 1초에 한 번 묶어서 전송. 네트워크 부하와 실시간성의 트레이드오프.
Companion Specification을 왜 써야 하나?
OPC UA 노드 구조를 직접 설계하면 업체마다 다른 방식으로 데이터가 노출되어 이기종 툴과의 호환 불가. Companion Spec(예: OPC UA for Pumps)을 따르면 어떤 OPC UA 클라이언트나 SCADA도 표준 구조로 자동 인식. 데이터 모델 설계 비용 절감 + 상호운용성 보장.
