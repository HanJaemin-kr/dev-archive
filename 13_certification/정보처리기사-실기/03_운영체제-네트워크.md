# 03. 운영체제 · 네트워크 (빈출)

> 정보처리기사 실기(NCS 2020 개정) 단답/서술형 대비 빈출 정리.
> ⭐ = 최빈출. 프로그래밍 코드 출력 문제는 제외(단, 유닉스/리눅스 명령어·chmod 권한 계산은 포함).

---

# 1부. 운영체제 (Operating System)

## 1-1. 프로세스 상태 전이 · PCB ⭐

**개념**
- **프로세스(Process)**: 실행 중인 프로그램. 자원(CPU·메모리 등)을 할당받는 단위.
- **PCB(Process Control Block, 프로세스 제어 블록)**: 운영체제가 프로세스를 관리하기 위해 프로세스마다 유지하는 정보 블록. 문맥교환(Context Switching) 시 저장/복원의 대상.

**프로세스 상태(5가지)**

| 상태 | 설명 |
|---|---|
| 생성(New) | 프로세스가 생성된 상태 |
| 준비(Ready) | CPU 할당을 기다리는 상태 (준비 큐 대기) |
| 실행(Run) | CPU를 할당받아 실행 중인 상태 |
| 대기(Wait / Block) | 입출력 등 이벤트 발생을 기다리는 상태 |
| 종료(Terminated / Exit) | 실행이 끝난 상태 |

**상태 전이(Transition) 용어** — ⭐ 단답 자주 출제

| 전이 | 이름 | 설명 |
|---|---|---|
| 준비 → 실행 | **디스패치(Dispatch)** | 준비 큐의 프로세스에 CPU 할당 |
| 실행 → 준비 | **타임아웃(Timeout)** / 선점(Preemption) | 할당 시간(타임 슬라이스) 초과로 CPU 회수 |
| 실행 → 대기 | **블록(Block)** | I/O 요청 등으로 대기 |
| 대기 → 준비 | **웨이크업(Wake-up)** | I/O 완료 등으로 다시 준비 큐로 |

**자주 나오는 출제형태:**
- "준비 상태에서 실행 상태로 전이하는 과정을 무엇이라 하는가?" → **디스패치(Dispatch)**
- "실행 중인 프로세스가 할당 시간 초과로 준비 상태로 가는 것?" → **타임아웃(Timeout)**
- "운영체제가 프로세스를 관리하기 위한 정보를 담은 자료구조?" → **PCB(프로세스 제어 블록)**

**핵심 답/암기:**
- 상태 5개: 생성·준비·실행·대기·종료.
- 디스패치(준비→실행), 타임아웃(실행→준비), 블록(실행→대기), 웨이크업(대기→준비).

## 1-2. 프로세스 vs 스레드

| 구분 | 프로세스(Process) | 스레드(Thread) |
|---|---|---|
| 정의 | 실행 중인 프로그램(자원 할당 단위) | 프로세스 내 실행 흐름(CPU 스케줄링 단위) |
| 자원 | 독립된 메모리 공간(코드·데이터·힙·스택) | 코드·데이터·힙 **공유**, 스택은 별도 |
| 통신 | IPC(비용 큼) | 같은 주소공간 공유(비용 작음) |
| 문맥교환 | 무거움 | 가벼움 |

**핵심 답/암기:** 스레드는 **스택만 별도**, 나머지(코드·데이터·힙)는 공유. 스레드는 "경량 프로세스(LWP)".

## 1-3. CPU 스케줄링 ⭐⭐

**개념**: 준비 큐의 프로세스 중 어느 것에 CPU를 할당할지 결정.

**선점(Preemptive) vs 비선점(Non-preemptive)**
- **선점형**: 실행 중인 프로세스의 CPU를 강제로 빼앗을 수 있음.
- **비선점형**: 한 번 CPU를 잡으면 끝나거나 스스로 반납할 때까지 유지.

| 구분 | 알고리즘 |
|---|---|
| **선점형** | **RR**(라운드로빈)·**SRT**(Shortest Remaining Time)·**다단계 큐**(Multi-level Queue)·**다단계 피드백 큐**(MLFQ)·**(선점형) 우선순위** |
| **비선점형** | **FCFS**(FIFO)·**SJF**(Shortest Job First)·**HRN**·**(비선점형) 우선순위**·**기한부(Deadline)** |

**주요 알고리즘**

| 알고리즘 | 유형 | 기준 |
|---|---|---|
| FCFS | 비선점 | 도착 순서(먼저 온 것 먼저) |
| SJF | 비선점 | 실행시간 짧은 것 먼저 (기아 발생 가능) |
| SRT | 선점 | 남은 실행시간 짧은 것 먼저 (SJF의 선점판) |
| HRN | 비선점 | 응답률(우선순위 값) 큰 것 먼저 → SJF의 기아 보완 |
| RR | 선점 | 시간 할당량(Time Quantum)만큼 순환 |
| 우선순위 | 선점/비선점 | 우선순위 높은 것 먼저 (Aging으로 기아 방지) |

### HRN 우선순위 공식 ⭐⭐ (실기 계산 최빈출)

$$
\text{우선순위} = \frac{\text{대기 시간} + \text{서비스(실행) 시간}}{\text{서비스(실행) 시간}}
$$

- **값이 클수록 우선순위가 높다.**
- 대기 시간이 긴 프로세스도 우선순위가 올라가 **SJF의 기아(Starvation) 문제를 보완**.

**계산 예시**

| 프로세스 | 대기시간 | 서비스시간 | HRN 값 = (대기+서비스)/서비스 |
|---|---|---|---|
| A | 5 | 20 | (5+20)/20 = **1.25** |
| B | 10 | 10 | (10+10)/10 = **2.0** |
| C | 15 | 5 | (15+5)/5 = **4.0** ← 최우선 |

→ 실행 순서: **C → B → A**

**자주 나오는 출제형태:**
- "HRN 스케줄링에서 우선순위 계산식을 쓰시오." → **(대기시간 + 서비스시간) / 서비스시간**
- 표 주고 "HRN 방식일 때 우선순위가 가장 높은 프로세스?" → 값 계산 후 최댓값.
- "선점형 스케줄링 기법 2가지를 쓰시오." → RR, SRT (또는 다단계 큐/피드백 큐).

**핵심 답/암기:**
- **HRN = (대기시간 + 서비스시간) / 서비스시간, 값 클수록 우선.**
- 선점: RR·SRT·다단계큐·다단계피드백큐·(선점)우선순위.
- 비선점: FCFS·SJF·HRN·(비선점)우선순위·기한부.

## 1-4. 교착상태(Deadlock) ⭐⭐

**개념**: 둘 이상의 프로세스가 서로 상대가 가진 자원을 기다리며 무한 대기하는 상태.

| 조건 | 영문 | 설명 |
|---|---|---|
| **상호 배제** | Mutual Exclusion | 한 자원을 한 번에 한 프로세스만 사용 |
| **점유와 대기** | Hold and Wait | 자원을 가진 채 다른 자원을 기다림 |
| **비선점** | No Preemption | 자원을 강제로 빼앗을 수 없음 |
| **환형 대기** | Circular Wait | 프로세스들이 원형으로 서로의 자원을 대기 |

### 교착상태 해결 방법 (예·회·발·회)

| 방법 | 설명 |
|---|---|
| **예방(Prevention)** | 4대 조건 중 하나 이상을 원천 차단 |
| **회피(Avoidance)** | 안전 상태 유지하며 할당 → **은행원 알고리즘(Banker's Algorithm, Dijkstra)** |
| **발견/탐지(Detection)** | 교착 발생 여부를 주기적으로 검사 |
| **회복(Recovery)** | 프로세스 강제 종료 또는 자원 선점(회수)으로 복구 |

**자주 나오는 출제형태:**
- "교착상태 발생 4가지 조건을 모두 쓰시오." → 상호배제·점유와대기·비선점·환형대기.
- "교착상태 회피 기법으로 사용하는 대표 알고리즘은?" → **은행원 알고리즘(Banker's Algorithm)**.

**핵심 답/암기:** 4조건 = **상·점·비·환** / 해결 = **예방·회피·발견·회복**, 회피=은행원 알고리즘.

## 1-5. 페이지 교체 알고리즘 ⭐⭐

**개념**: 요구 페이징에서 프레임이 꽉 찼을 때 어떤 페이지를 내보낼지(교체) 결정. 없는 페이지 참조 시 **페이지 부재(Page Fault)** 발생.

| 알고리즘 | 교체 기준 |
|---|---|
| **FIFO** | 가장 먼저 들어온 페이지 교체 |
| **LRU**(Least Recently Used) | **가장 오래 사용되지 않은**(참조 안 된) 페이지 교체 |
| **LFU**(Least Frequently Used) | 사용 **빈도가 가장 낮은** 페이지 교체 |
| **NUR**(Not Used Recently) | 참조·변형 비트로 최근 미사용 페이지 교체 (LRU 근사) |
| **OPT**(Optimal, 최적) | 앞으로 **가장 오래 사용 안 될** 페이지 교체 (이론상 최적, 구현 불가) |

- **벨레이디의 모순(Belady's Anomaly)**: **FIFO**에서 프레임 수를 늘렸는데 오히려 페이지 부재가 증가하는 현상.

**계산 예시** — FIFO, 프레임 3개, 참조열 `2 3 2 1 5 2 4 5 3 2 5 2`
- 결과: 페이지 부재 다수 발생(표를 그려 하나씩 채우며 F/H 표기하는 방식으로 계산). 시험에서는 프레임을 표로 그려 **적재/교체 후 부재 횟수**를 세면 됨.

**계산 요령(빈출)**
1. 참조 페이지가 프레임에 있으면 **적중(Hit)**, 없으면 **부재(Fault)** → 새 페이지 적재.
2. 프레임이 꽉 찬 상태에서 부재 발생 시 알고리즘 기준으로 하나 교체.
3. LRU는 "가장 오래 안 쓴 것", FIFO는 "가장 먼저 들어온 것" 교체.

**자주 나오는 출제형태:**
- "프레임 N개, 참조 문자열이 다음과 같을 때 FIFO(또는 LRU)로 페이지 부재 횟수를 구하시오."
- "프레임 증가 시 부재가 오히려 증가하는 현상을 무엇이라 하는가?" → **벨레이디의 모순(Belady's Anomaly)**.
- "구현이 불가능한 이론상 최적 알고리즘은?" → **OPT**.

**핵심 답/암기:** FIFO·LRU·LFU·NUR·OPT. 벨레이디 모순=FIFO. LRU=오래 미사용, LFU=빈도 최소, OPT=미래 최적.

## 1-6. 메모리 관리 · 배치 전략

**페이징 vs 세그먼테이션**

| 구분 | 페이징(Paging) | 세그먼테이션(Segmentation) |
|---|---|---|
| 분할 단위 | 고정 크기(페이지) | 가변 크기(논리 단위: 함수·배열 등) |
| 단편화 | **내부 단편화** 발생 | **외부 단편화** 발생 |
| 매핑 | 페이지 테이블 | 세그먼트 테이블(base+limit) |

- **내부 단편화(Internal Fragmentation)**: 할당된 공간이 요청보다 커서 내부에 남는 낭비 공간.
- **외부 단편화(External Fragmentation)**: 사용 가능한 총량은 충분하나 조각나서(연속 공간 부족) 할당 못 하는 낭비.

**배치 전략(Placement Strategy)** — 빈 공간에 새 프로세스를 어디에 넣을지

| 전략 | 설명 |
|---|---|
| **최초 적합**(First Fit) | 들어갈 수 있는 **첫 번째** 공간에 배치 |
| **최적 적합**(Best Fit) | 들어갈 수 있는 공간 중 **가장 작은**(남는 조각 최소) 공간 |
| **최악 적합**(Worst Fit) | 들어갈 수 있는 공간 중 **가장 큰** 공간 |

**계산 예시** — 빈 공간 `[20K, 16K, 8K]`, 요청 `12K`
- 최초 적합 → 20K (첫 번째로 들어가는 곳)
- 최적 적합 → 16K (12K가 들어가는 것 중 가장 작음) → 남은 조각 4K
- 최악 적합 → 20K (가장 큼) → 남은 조각 8K

**핵심 답/암기:** 페이징=내부 단편화, 세그먼테이션=외부 단편화. 최초/최적/최악 적합 = First/Best/Worst Fit.

## 1-7. 가상기억장치(Virtual Memory)

| 용어 | 설명 |
|---|---|
| **요구 페이징**(Demand Paging) | 실제로 필요한 페이지만 그때그때 메모리에 적재 |
| **워킹 셋**(Working Set) | 특정 시점에 프로세스가 자주 참조하는 페이지 집합 → 스래싱 방지 목적 |
| **스래싱**(Thrashing) | 페이지 부재가 과도해 CPU가 실제 작업보다 페이지 교체(swap)에만 매달리는 현상 → 성능 급락 |
| **지역성**(Locality) | 참조가 특정 영역에 집중되는 경향 |

**지역성 2종** ⭐
- **시간 지역성(Temporal Locality)**: 한 번 참조한 항목을 곧 다시 참조 (예: 반복문, 순환, 스택).
- **공간 지역성(Spatial Locality)**: 참조한 항목 근처를 곧 참조 (예: 배열 순회, 순차 접근).

**스래싱 방지책:** 워킹 셋 유지, 페이지 부재 빈도(PFF) 조절, 다중 프로그래밍 정도(Degree) 조절.

**자주 나오는 출제형태:**
- "페이지 부재가 지나치게 많아 성능이 급격히 저하되는 현상은?" → **스래싱(Thrashing)**.
- "지역성의 2가지 종류를 쓰시오." → **시간 지역성, 공간 지역성**.
- "자주 참조하는 페이지 집합을 무엇이라 하는가?" → **워킹 셋(Working Set)**.

## 1-8. 디스크 스케줄링

| 알고리즘 | 동작 |
|---|---|
| **FCFS** | 요청 순서대로 처리 |
| **SSTF**(Shortest Seek Time First) | 현재 헤드에서 **가장 가까운** 트랙 먼저 (기아 가능) |
| **SCAN** | 한쪽 끝까지 갔다가 방향을 바꿔 반대 끝으로 (엘리베이터) |
| **C-SCAN** | 한 방향으로만 서비스, 끝에 도달하면 처음으로 되돌아가 다시 한 방향 (응답 균등) |
| **LOOK** | SCAN과 유사하되 **요청이 있는 마지막 지점까지만** 이동 후 방향 전환 |

**핵심 답/암기:** SSTF=가장 가까운 것 먼저 / SCAN=엘리베이터(양방향) / C-SCAN=한 방향+처음 복귀 / LOOK=요청 끝까지만.

### chmod 권한 계산 ⭐⭐ (실기 최빈출)

**권한 종류**: `r`(읽기 read)=**4**, `w`(쓰기 write)=**2**, `x`(실행 execute)=**1**
**대상 3자리**: **소유자(Owner / User) → 그룹(Group) → 기타(Other)** 순서.

| 8진수 | 2진수 | 기호 | 의미 |
|---|---|---|---|
| 7 | 111 | rwx | 읽기+쓰기+실행 (4+2+1) |
| 6 | 110 | rw- | 읽기+쓰기 (4+2) |
| 5 | 101 | r-x | 읽기+실행 (4+1) |
| 4 | 100 | r-- | 읽기 |
| 0 | 000 | --- | 권한 없음 |

**대표 예시**
- `chmod 755 file` → **rwxr-xr-x** (소유자 rwx=7 / 그룹 r-x=5 / 기타 r-x=5)
- `chmod 644 file` → **rw-r--r--** (소유자 rw-=6 / 그룹 r--=4 / 기타 r--=4)
- `chmod 777 file` → **rwxrwxrwx** (모두 7)
- `chmod 700 file` → **rwx------** (소유자만 rwx)

**역산(기호→숫자) 예시**
- `rwxr-xr--` → 소유자 rwx=7, 그룹 r-x=5, 기타 r--=4 → **754**
- `rw-rw-r--` → 6·6·4 → **664**

**자주 나오는 출제형태:**
- "`chmod 751` 실행 시 권한을 기호(rwx)로 표기하시오." → **rwxr-x--x** (7=rwx, 5=r-x, 1=--x)
- "소유자에게 모든 권한, 그룹·기타에게 읽기·실행만 부여하는 chmod 명령을 8진수로 쓰시오." → **755**
- "파일 소유자를 변경하는 명령어는?" → **chown**

**핵심 답/암기:**
- **r=4, w=2, x=1**. 세 자리 = **소유자·그룹·기타**.
- **755 = rwxr-xr-x**, 644 = rw-r--r--, 777 = rwxrwxrwx.
- **파일 디스크립터(File Descriptor)**: 프로세스가 파일을 식별하는 정수. **0=표준입력(stdin), 1=표준출력(stdout), 2=표준에러(stderr)**.

## 2-3. TCP vs UDP ⭐

| 구분 | **TCP** | **UDP** |
|---|---|---|
| 연결 방식 | 연결 지향(Connection-oriented) | 비연결(Connectionless) |
| 신뢰성 | 높음(순서 보장·재전송·흐름/혼잡 제어) | 낮음(보장 없음) |
| 속도 | 상대적으로 느림 | 빠름 |
| 헤더 크기 | 20바이트(가변) | 8바이트(고정) |
| 전송 단위 | 세그먼트(Segment) | 데이터그램(Datagram) |
| 용도 | 웹·메일·파일전송(정확성 필요) | 스트리밍·DNS·VoIP(속도 필요) |

**3-way handshake (연결 설정)**: `SYN → SYN+ACK → ACK`
**4-way handshake (연결 해제)**: `FIN → ACK → FIN → ACK`

**자주 나오는 출제형태:**
- "TCP 연결 설정 3단계 과정을 쓰시오." → SYN → SYN+ACK → ACK (3-way handshake).
- "비연결형이며 신뢰성보다 속도를 우선하는 전송 계층 프로토콜은?" → **UDP**.

## 2-4. 주요 프로토콜 ⭐

| 프로토콜 | 계층 | 기능 |
|---|---|---|
| **IP** | 네트워크 | 논리주소 지정, 패킷 라우팅 (비신뢰·비연결) |
| **ICMP** | 네트워크 | 오류·상태 보고 메시지 (ping) |
| **ARP** ⭐ | 네트워크 | **IP 주소 → MAC 주소** 변환 |
| **RARP** ⭐ | 네트워크 | **MAC 주소 → IP 주소** 변환 |
| **IGMP** | 네트워크 | 멀티캐스트 그룹 관리 |
| **TCP** | 전송 | 연결지향·신뢰성 전송 |
| **UDP** | 전송 | 비연결·고속 전송 |
| **HTTP(S)** | 응용 | 웹 문서 전송 (HTTPS = HTTP+TLS/SSL 암호화) |
| **FTP** | 응용 | 파일 전송 (제어 21번, 데이터 20번 포트) |
| **SMTP** | 응용 | 메일 **발신**(전송) |
| **POP3** | 응용 | 메일 **수신**(서버→클라이언트 다운로드) |
| **DNS** | 응용 | 도메인 이름 ↔ IP 주소 변환 |
| **DHCP** | 응용 | IP 주소 자동 할당 |
| **SNMP** | 응용 | 네트워크 장비 관리·모니터링 |
| **Telnet** | 응용 | 원격 접속 (평문, 비암호화) |
| **SSH** | 응용 | 원격 접속 (암호화) |

**자주 나오는 출제형태:**
- "IP 주소를 물리(MAC) 주소로 변환하는 프로토콜은?" → **ARP** (반대는 RARP).
- "메일 발신 프로토콜과 수신 프로토콜을 각각 쓰시오." → 발신 **SMTP**, 수신 **POP3**(또는 IMAP).
- "IP를 자동으로 할당해주는 프로토콜은?" → **DHCP**.

**핵심 답/암기:** **ARP = IP→MAC**, **RARP = MAC→IP** (혼동 주의). SMTP=발신, POP3=수신.

## 2-5. IP 주소 · 서브넷팅 ⭐

**IPv4**: 32비트, 8비트씩 4옥텟 점 표기(예: `192.168.0.1`).

| 클래스 | 첫 옥텟 범위 | 기본 서브넷 마스크 | 용도 |
|---|---|---|---|
| A | 0 ~ 127 | 255.0.0.0 (/8) | 대규모 |
| B | 128 ~ 191 | 255.255.0.0 (/16) | 중규모 |
| C | 192 ~ 223 | 255.255.255.0 (/24) | 소규모 |
| D | 224 ~ 239 | - | 멀티캐스트 |
| E | 240 ~ 255 | - | 연구·예약 |

**서브넷팅 계산 요령**
- 호스트 비트 수 `h`일 때 서브넷 내 **총 주소 = 2^h**, **사용 가능 호스트 = 2^h − 2** (네트워크 주소·브로드캐스트 주소 제외).
- 예) `/26` → 호스트 비트 32−26 = 6 → 총 64개, 사용 가능 **62개**. 서브넷 마스크 = **255.255.255.192**.
- 예) C클래스를 4개 서브넷으로 → 서브넷 비트 2개(2²=4) 빌림 → `/26`, 각 서브넷 호스트 62개.

**IPv6** ⭐
- **128비트** 주소. 16비트씩 8그룹을 콜론(`:`)으로 16진수 표기.
- 주소 유형: **유니캐스트(1:1)·멀티캐스트(1:다수 그룹)·애니캐스트(1:가장 가까운 하나)**. (IPv4의 브로드캐스트는 없음.)
- 장점: 주소 공간 확대, 헤더 단순화, 보안(IPSec) 기본, QoS 지원.

**CIDR(Classless Inter-Domain Routing)**: 클래스 구분 없이 `/prefix`로 네트워크 크기 지정(예: `192.168.1.0/26`).

**자주 나오는 출제형태:**
- "IPv6 주소의 비트 수는?" → **128비트**.
- "`/26` 서브넷에서 사용 가능한 호스트 수는?" → **62개** (2^6−2).
- "IPv6 주소 3가지 전송 방식을 쓰시오." → 유니캐스트·멀티캐스트·애니캐스트.

**핵심 답/암기:** IPv4=32비트, **IPv6=128비트**. 사용 호스트=2^(호스트비트)−2.

## 2-6. 라우팅 프로토콜

| 구분 | 프로토콜 | 방식 | 특징 |
|---|---|---|---|
| **IGP**(내부) | **RIP** | 거리 벡터(Distance Vector) | 홉(hop) 수 기준, **최대 15홉**(16=무한대), 소규모 |
| **IGP**(내부) | **OSPF** | 링크 상태(Link State) | 비용(대역폭) 기반 최단경로(SPF), 대규모, 빠른 수렴 |
| **EGP**(외부) | **BGP** | 경로 벡터(Path Vector) | AS(자율시스템) 간 라우팅, 인터넷 백본 |

**자주 나오는 출제형태:**
- "거리 벡터 방식이며 홉 수 최대 15로 제한되는 내부 라우팅 프로토콜은?" → **RIP**.
- "링크 상태 방식의 대표 IGP는?" → **OSPF**.
- "자율 시스템(AS) 간 라우팅에 쓰이는 외부 라우팅 프로토콜은?" → **BGP**.

**핵심 답/암기:** RIP=거리벡터·홉15제한 / OSPF=링크상태 / BGP=EGP·AS간.

## 2-7. 네트워크 장비 (계층별) ⭐

| 장비 | 동작 계층 | 기능 |
|---|---|---|
| **리피터**(Repeater) | 물리(L1) | 감쇠 신호 증폭·재생 |
| **허브**(Hub) | 물리(L1) | 여러 노드 연결, 신호 브로드캐스트(멀티포트 리피터) |
| **브리지**(Bridge) | 데이터링크(L2) | MAC 주소 기반 세그먼트 연결·필터링 |
| **스위치**(Switch) | 데이터링크(L2) | MAC 기반 포트별 전송(브리지 발전형) |
| **라우터**(Router) | 네트워크(L3) | IP 기반 경로 선택(라우팅), 서로 다른 네트워크 연결 |
| **게이트웨이**(Gateway) | 전송(L4) 이상 | 서로 다른 프로토콜/네트워크 간 변환·중계 |

**자주 나오는 출제형태:**
- "MAC 주소를 기반으로 프레임을 스위칭하는 데이터링크 계층 장비는?" → **스위치**(또는 브리지).
- "서로 다른 네트워크를 IP 기반으로 연결하고 경로를 결정하는 장비는?" → **라우터**(L3).
- "프로토콜이 다른 네트워크를 상호 연결·변환하는 장비는?" → **게이트웨이**.

**핵심 답/암기:** L1=리피터·허브 / L2=브리지·스위치 / L3=라우터 / L4↑=게이트웨이.
