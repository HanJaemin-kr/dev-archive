# 04. 소프트웨어 개발 보안 (빈출)

> 정보처리기사 실기(NCS 2020 개정) 대비 빈출 정리 노트 — 단답/서술형 중심.
> ⭐ = 최빈출. 프로그래밍 코드 문제 제외, 개념·용어 암기 위주.

---

## 1. 정보보안 3요소 (CIA) ⭐

- **기밀성 (Confidentiality)**: 인가된 사용자만 정보에 접근 가능 (비인가 노출 방지). 예) 암호화, 접근통제.
- **무결성 (Integrity)**: 인가된 사용자만 정보를 수정 가능 (비인가 변경·훼손 방지). 예) 해시, 디지털 서명.
- **가용성 (Availability)**: 인가된 사용자가 필요할 때 자원에 접근 가능. 예) 이중화, 백업, DDoS 방어.

**추가 보안 목표 (자주 같이 출제)**

- **인증 (Authentication)**: 정당한 사용자/객체 여부 확인.
- **부인방지 (Non-repudiation)**: 송·수신 사실을 부인하지 못하게 함 (디지털 서명으로 보장).
- **책임추적성 (Accountability)**: 행위 주체를 추적 가능 (로그·감사).

`자주 나오는 출제형태:`

- "정보보안의 3대 요소를 쓰시오" → **기밀성, 무결성, 가용성**
- "인가되지 않은 자가 정보를 변경하지 못하게 하는 보안 요소는?" → **무결성(Integrity)**
- "송신자가 전송 사실을 부인하지 못하게 하는 것은?" → **부인방지(Non-repudiation)**

`핵심 답/암기:` **CIA = 기밀성·무결성·가용성**. 기밀성=노출방지, 무결성=변경방지, 가용성=사용가능.

<sub>대칭키는 하나의 비밀키를 공유해 빠르지만 키 배송 문제가 있고, 비대칭키는 공개키·개인키 쌍을 써서 키 관리가 쉽지만 느리다.</sub>

### 2-1. 대칭키(비밀키) 암호 — 양방향

- 암호화 키 = 복호화 키 (하나의 비밀키 공유), 속도 빠름, 대용량에 적합.
- **키 배송(공유) 문제** 존재 → 사용자 n명일 때 필요한 **키 개수 = n(n-1)/2**.
- **블록 암호**: 데이터를 일정 크기 블록 단위로 암호화 (DES, 3DES, AES, SEED, ARIA, IDEA).
- **스트림 암호**: 비트/바이트 단위로 연속 암호화 (RC4, LFSR).

| 알고리즘 | 특징 |
|---|---|
| **DES** | 64비트 블록, 56비트 키. 현재는 취약 |
| **3DES** | DES를 3번 반복 |
| **AES** ⭐ | DES 대체 표준. 128/192/256비트 키, 블록 암호 |
| **SEED** ⭐ | 국산(KISA). 128/256비트 |
| **ARIA** ⭐ | 국산(국정원·학계·연구소 협력). 128/192/256비트 |
| **IDEA** | 128비트 키 블록 암호 (PGP에 사용) |
| **RC4** | 스트림 암호 |
| **LFSR** | 선형 귀환 시프트 레지스터, 스트림 암호 기반 |

### 2-2. 비대칭키(공개키) 암호 — 양방향

- 암호화 키 ≠ 복호화 키 (공개키/개인키 쌍), 키 관리 쉬움, 속도 느림.
- **기밀성(암호화)**: 수신자의 **공개키**로 암호화 → 수신자의 **개인키**로 복호화.
- **전자서명**: 송신자의 **개인키**로 서명 → 송신자의 **공개키**로 검증. (부인방지·무결성)

| 알고리즘 | 기반 수학 문제 / 용도 |
|---|---|
| **RSA** ⭐ | **소인수분해**의 어려움. 암호화+서명 |
| **ECC** | **타원곡선(이산대수)**. 짧은 키로 높은 안전성 |
| **ElGamal** | 이산대수 문제 |
| **Diffie-Hellman(DH)** ⭐ | **키 교환(공유) 전용** 프로토콜 |
| **DSA** | 전자서명 전용(Digital Signature Algorithm) |

### 2-3. 해시(단방향) 암호 — 복호화 불가

- 임의 길이 입력 → 고정 길이 출력(**메시지 다이제스트**). **복호화 불가능(단방향)**.
- 무결성 검증·비밀번호 저장에 사용. **Salt**(임의 값 추가)로 레인보우 테이블 공격 방어.
- 종류: **MD5**(128비트), **SHA-1 / SHA-256 / SHA-512**(SHA 계열), **HAVAL**, **SNEFRU**, **HAS-160**(국산).

`자주 나오는 출제형태:`

- "국산 대칭키 암호 알고리즘 2가지?" → **SEED, ARIA**
- "소인수분해 기반 공개키 알고리즘은?" → **RSA**
- "공개키 방식에서 키 교환(공유)에 사용되는 알고리즘은?" → **Diffie-Hellman(DH)**
- "n명이 대칭키로 통신할 때 필요한 키의 총 개수는?" → **n(n-1)/2**
- "복호화가 불가능한 단방향 암호 방식과 대표 알고리즘은?" → **해시(MD5, SHA)**
- "패스워드 해시 저장 시 무작위 값을 덧붙여 사전/레인보우 공격을 막는 것은?" → **Salt**

`핵심 답/암기:`
**대칭키 = DES·3DES·AES·SEED·ARIA·IDEA·RC4·LFSR** / **비대칭키 = RSA·ECC·ElGamal·DH·DSA** / **해시 = MD5·SHA·HAVAL·SNEFRU**.
공개키로 **암호화**, 개인키로 **서명**. 절대 혼동 금지.

## 3. 공격 유형 ⭐ (최빈출)

### 3-1. 서비스 거부 공격 (DoS / DDoS)

| 공격 | 정의(한 줄) |
|---|---|
| **DoS** | 시스템 자원을 고갈시켜 정상 서비스를 방해 |
| **DDoS** ⭐ | 다수의 좀비 PC(봇넷)로 동시 대량 트래픽을 보내는 분산 서비스 거부 |
| **SYN Flooding** ⭐ | TCP 3-way handshake의 SYN 요청만 대량 전송, 연결 대기열(백로그) 고갈 |
| **Smurf** | 출발지를 위조(피해자 IP)해 브로드캐스트로 ICMP를 보내 응답 폭주 유발 |
| **Ping of Death** | 규정보다 큰 비정상 ICMP 패킷을 보내 시스템 마비 |
| **TearDrop** | IP 패킷의 Fragment offset을 조작해 재조합 오류 유발 |
| **LAND Attack** | 출발지·목적지 IP를 동일하게(피해자 자신) 위조해 무한 응답 유발 |
| **HTTP GET Flooding** | 동일 URL에 대량 HTTP GET 요청으로 웹서버 자원 고갈 |
| **Slowloris** | HTTP 요청 헤더를 조금씩·느리게 보내 연결을 오래 점유 (Slow HTTP) |

### 3-2. 웹 애플리케이션 공격

| 공격 | 정의(한 줄) |
|---|---|
| **SQL Injection** ⭐ | 입력값에 악의적 SQL을 삽입해 DB 조작·정보 탈취 |
| **XSS (크로스사이트 스크립팅)** ⭐ | 웹페이지에 악성 스크립트를 삽입해 사용자 브라우저에서 실행 |
| **CSRF (크로스사이트 요청 위조)** ⭐ | 인증된 사용자의 권한을 도용해 의도치 않은 요청 전송 |
| **파일 업로드 취약점** | 웹셸 등 악성 실행 파일을 업로드해 서버 장악 |
| **디렉터리 트래버설(Traversal)** | `../` 등 경로 조작으로 상위 디렉터리의 파일에 접근 |

> **XSS vs CSRF 비교**: XSS = 스크립트 삽입해 **사용자(브라우저) 공격** / CSRF = 인증정보를 도용해 **서버에 위조 요청**.

### 3-3. 네트워크 공격

| 공격 | 정의(한 줄) |
|---|---|
| **스니핑(Sniffing)** | 네트워크 패킷을 몰래 도청·수집 (수동적 공격) |
| **스푸핑(Spoofing)** | 출발지 정보를 위조 — IP / ARP / DNS Spoofing |
| **세션 하이재킹** | 이미 인증된 세션을 탈취해 정상 사용자로 위장 |
| **중간자 공격(MITM)** | 통신 양단 사이에 끼어들어 도청·변조 |

### 3-4. 인증/계정 탈취 공격

| 공격 | 정의(한 줄) |
|---|---|
| **무차별 대입(Brute Force)** | 가능한 모든 경우의 수로 비밀번호를 시도 |
| **사전 공격(Dictionary)** | 사전 단어·자주 쓰는 문자열 목록으로 비밀번호 추측 |
| **크리덴셜 스터핑** | 유출된 아이디/비번 목록을 다른 사이트에 대입 |
| **레인보우 테이블** | 해시값-원문 대응표를 미리 만들어 역추적 (Salt로 방어) |

### 3-5. 악성코드 / 지능형 공격

| 유형 | 정의(한 줄) |
|---|---|
| **APT** ⭐ | 특정 대상을 장기간 은밀히 지속 공격하는 지능형 지속 위협 |
| **랜섬웨어** ⭐ | 파일을 암호화하고 복호화 대가로 금전 요구 |
| **제로데이(Zero-day)** | 패치가 나오기 전 취약점을 악용하는 공격 |
| **백도어** | 인증을 우회해 재접속하도록 몰래 심은 통로 |
| **루트킷** | 침입 흔적·프로세스를 숨기는 악성 도구 모음 |
| **트로이목마** | 정상 프로그램으로 위장, 자기복제 없음 |
| **웜(Worm)** | 스스로 복제·전파 (숙주 불필요) |
| **바이러스** | 숙주 파일에 기생해 복제·감염 |
| **논리폭탄** | 특정 조건 충족 시 악성 동작이 발현되도록 심어둔 코드 |

### 3-6. 사회공학(Social Engineering) 공격

| 유형 | 정의(한 줄) |
|---|---|
| **피싱(Phishing)** | 위장 이메일·사이트로 개인정보 탈취 |
| **스미싱(Smishing)** | 문자메시지(SMS) 속 악성 링크로 유도 |
| **파밍(Pharming)** | DNS·hosts 변조로 정상 주소 입력해도 위조 사이트로 유도 |
| **큐싱(Qshing)** | 악성 QR코드로 유도 |
| **보이스피싱(Vishing)** | 전화 음성으로 속여 정보·금전 탈취 |
| **스캠(Scam)** | 이메일 등으로 거래 상대를 속여 금전을 가로챔 |

`자주 나오는 출제형태:`

- "TCP 연결 요청(SYN)만 대량 전송해 서버 연결 자원을 고갈시키는 공격은?" → **SYN Flooding**
- "출발지·목적지 IP를 피해자로 동일하게 위조하는 공격은?" → **LAND Attack**
- "입력값에 악성 SQL을 삽입해 DB를 조작하는 공격은?" → **SQL Injection**
- "인증된 사용자의 권한을 이용해 의도하지 않은 요청을 서버에 보내는 공격은?" → **CSRF**
- "웹페이지에 악성 스크립트를 삽입해 사용자 브라우저에서 실행시키는 공격은?" → **XSS**
- "정상 프로그램으로 위장하지만 자기복제는 하지 않는 악성코드는?" → **트로이목마**
- "DNS/hosts를 변조해 정상 URL 입력에도 가짜 사이트로 유도하는 공격은?" → **파밍(Pharming)**

`핵심 답/암기:` 서비스거부=자원고갈 / SQLi·XSS·CSRF는 웹 3대 / 웜=자기복제O·트로이목마=복제X / 파밍=DNS변조·피싱=위장사이트.

<sub>DAC=소유자가 권한을 임의로 준다, MAC=보안등급 규칙으로 강제 통제, RBAC=사람이 아니라 역할에 권한을 준다.</sub>

| 모델 | 정식 명칭 | 권한 부여 기준 |
|---|---|---|
| **DAC** ⭐ | Discretionary Access Control (임의적 접근통제) | **신분(ID) 기반**, 데이터 **소유자**가 권한 부여 |
| **MAC** ⭐ | Mandatory Access Control (강제적 접근통제) | **규칙·보안등급** 기반, **시스템(관리자)**이 강제 |
| **RBAC** ⭐ | Role Based Access Control (역할 기반 접근통제) | **역할(직무)** 기반, 역할에 권한 할당 |

- **접근통제 행렬(Access Control Matrix)**: 행=주체(Subject), 열=객체(Object), 각 칸=허용된 접근 권한.

`자주 나오는 출제형태:`

- "데이터 소유자가 다른 사용자에게 접근 권한을 부여하는 신분 기반 접근통제는?" → **DAC**
- "보안 등급(규칙)에 따라 시스템이 강제로 접근을 통제하는 방식은?" → **MAC**
- "역할에 권한을 부여하고 사용자에게 역할을 할당하는 접근통제는?" → **RBAC**

`핵심 답/암기:` **D**AC=소유자(임의)·**M**AC=강제(등급)·**R**BAC=역할.

## 5. 보안 프로토콜

| 프로토콜 | 계층/용도 | 핵심 |
|---|---|---|
| **SSL / TLS** ⭐ | 전송 계층 보안 | 서버·클라이언트 간 암호화 통신, HTTPS의 기반 |
| **IPSec** ⭐ | 네트워크(IP) 계층 보안 | VPN에 사용. **AH=인증·무결성**, **ESP=암호화+인증**, **전송 모드/터널 모드** |
| **SSH** | 원격 접속 보안 | Telnet 대체, 암호화된 원격 셸 |
| **S-HTTP** | 응용 계층 | HTTP 메시지 단위 암호화 (SSL과 별개) |
| **SET** | 전자상거래 결제 | 신용카드 결제 보안 프로토콜 |
| **PGP** | 이메일 보안 | 이메일 암호화·서명, 개인이 신뢰망 구성 |
| **S/MIME** | 이메일 보안 | 인증서(CA) 기반 이메일 암호화·서명 |
| **Kerberos** ⭐ | 인증 | **티켓(Ticket) 기반** 대칭키 인증, KDC(인증서버) 사용 |

- **IPSec 핵심 암기**: **AH(Authentication Header)** = 무결성·인증(암호화 X), **ESP(Encapsulating Security Payload)** = 기밀성(암호화) + 인증. 모드는 **전송 모드**(페이로드만) / **터널 모드**(패킷 전체, VPN).

`자주 나오는 출제형태:`

- "IPSec에서 데이터 암호화(기밀성)를 제공하는 프로토콜은?" → **ESP**
- "IPSec에서 인증·무결성만 제공하는 프로토콜은?" → **AH**
- "티켓 기반으로 사용자를 인증하는 대칭키 기반 인증 프로토콜은?" → **Kerberos**
- "웹 통신을 암호화하는 전송 계층 보안 프로토콜은?" → **SSL/TLS**

`핵심 답/암기:` **AH=인증, ESP=암호화**. Kerberos=티켓. SSL/TLS=HTTPS 기반.

## 6. 인증(Authentication) 기술

- **인증 유형(요소) 4가지**
  - **지식 기반 (Something you know)**: 패스워드, PIN, i-PIN.
  - **소유 기반 (Something you have)**: OTP, 보안 토큰, 스마트카드, 공동인증서.
  - **생체 기반 (Something you are)**: 지문, 홍채, 정맥, 얼굴.
  - **행위 기반 (Something you do)**: 서명, 걸음걸이, 타이핑 패턴.
- **다중요소 인증(MFA)**: 위 요소 2개 이상 결합 (예: 비번 + OTP).

| 기술 | 설명 |
|---|---|
| **SSO** ⭐ | Single Sign-On. 한 번 인증으로 여러 시스템 이용 |
| **OAuth 2.0** ⭐ | 비밀번호 없이 제3자 앱에 **접근 권한 위임**(인가) |
| **SAML** | XML 기반 인증·인가 정보 교환 표준 (기업 SSO에 사용) |
| **FIDO** | 생체·기기 기반 비밀번호 없는(패스워드리스) 인증 |

`자주 나오는 출제형태:`

- "한 번의 로그인으로 여러 서비스에 접근하는 인증 방식은?" → **SSO**
- "비밀번호 공유 없이 제3자에게 자원 접근 권한을 위임하는 표준은?" → **OAuth 2.0**
- "인증 요소 3가지(유형)를 쓰시오" → **지식 기반, 소유 기반, 생체 기반**

`핵심 답/암기:` 지식·소유·생체(·행위). SSO=한번로그인, OAuth=권한위임(인가), FIDO=비밀번호 없는 생체인증.

## 7. 시큐어 코딩 가이드 (KISA 7대 분류) ⭐

KISA/행정안전부 SW 개발 보안 가이드의 **7개 취약점 분류**:

| # | 분류 | 대표 취약점 |
|---|---|---|
| 1 | **입력데이터 검증 및 표현** ⭐ | SQL Injection, XSS, 버퍼 오버플로, 크로스사이트 요청 위조 |
| 2 | **보안 기능** | 부적절한 인가, 취약한 암호화 알고리즘, 하드코딩된 비밀번호 |
| 3 | **시간 및 상태** | 경쟁 조건(Race Condition), TOCTOU, 교착 상태 |
| 4 | **에러 처리** | 오류 메시지로 정보 노출, 예외 미처리 |
| 5 | **코드 오류** | Null 포인터 역참조, 자원 반환 없이 반복 사용 |
| 6 | **캡슐화** | 잘못된 접근 제어자, 민감 데이터 노출 |
| 7 | **API 오용** | 취약하거나 위험한 함수 사용, DNS lookup 신뢰 |

`자주 나오는 출제형태:`

- "SQL Injection·XSS 등을 방지하기 위한 시큐어 코딩 분류는?" → **입력데이터 검증 및 표현**
- "SW 개발 보안 가이드의 취약점 분류는 몇 개이며 대표적인 것은?" → **7개** (입력데이터 검증 및 표현 등)

`핵심 답/암기:` 7분류 = **입력검증 · 보안기능 · 시간및상태 · 에러처리 · 코드오류 · 캡슐화 · API오용**. 입력값 검증 미비 → SQLi·XSS 원인.

## 8. 보안 솔루션

| 솔루션 | 설명 |
|---|---|
| **방화벽(Firewall)** ⭐ | 미리 정의된 규칙으로 내·외부 네트워크 트래픽 필터링 |
| **IDS(침입탐지시스템)** ⭐ | 침입을 **탐지·경보** (오용 탐지 / 이상 탐지) |
| **IPS(침입방지시스템)** ⭐ | 침입을 탐지하고 **실시간 차단**까지 수행 |
| **WAF(웹방화벽)** ⭐ | 웹 공격(SQLi·XSS 등) 전용 방어 |
| **VPN** | 공중망에 암호화된 가상 사설 통신망 구성 |
| **DLP** | 데이터 유출 방지(Data Loss Prevention) |
| **ESM / SIEM** | 보안 이벤트 통합 관리·상관 분석 (SIEM=로그 분석 강화) |
| **NAC** | 네트워크 접근 제어, 비인가 단말 차단 |

> **IDS vs IPS**: IDS = **탐지·경보(수동)** / IPS = **탐지 + 차단(능동)**.

`자주 나오는 출제형태:`

- "침입을 탐지하고 실시간으로 차단까지 하는 솔루션은?" → **IPS**
- "웹 애플리케이션 공격을 전용으로 막는 방화벽은?" → **WAF**
- "여러 보안 장비의 로그·이벤트를 통합 수집·상관 분석하는 솔루션은?" → **SIEM(ESM)**

`핵심 답/암기:` 방화벽=규칙 필터링 / IDS=탐지 / IPS=차단 / WAF=웹 / SIEM=통합로그분석.

## 9. 정보보호 인증제도

| 제도 | 설명 |
|---|---|
| **ISMS-P** ⭐ | 정보보호 및 개인정보보호 관리체계 인증 (국내, KISA). ISMS(정보보호) + PIMS(개인정보) 통합 |
| **CC (Common Criteria)** ⭐ | 정보보호 제품의 보안성을 평가하는 **국제 공통평가기준(ISO/IEC 15408)**. 보증등급 **EAL0~EAL7** |

`자주 나오는 출제형태:`

- "정보보호 및 개인정보보호 관리체계 국내 인증제도는?" → **ISMS-P**
- "정보보호 제품의 보안성을 평가하는 국제 표준(공통평가기준)은?" → **CC (Common Criteria)**

`핵심 답/암기:` ISMS-P=관리체계 인증(국내), CC=제품 평가(국제, EAL 등급).

## 10. 디지털 서명 · PKI (선택)

- **디지털(전자) 서명**: 송신자의 **개인키로 서명** → 수신자가 송신자의 **공개키로 검증**.
  - 보장: **무결성**(위·변조 확인), **인증**(작성자 확인), **부인방지**(작성 사실 부인 불가).
  - 기밀성은 보장하지 않음(서명 ≠ 암호화).
- **PKI (공개키 기반구조, Public Key Infrastructure)**: 공개키 암호를 안전하게 관리하는 체계.
  - **CA(인증기관)**: 인증서 발급·관리.
  - **RA(등록기관)**: 사용자 신원 확인.
  - **인증서(Certificate)**: 공개키와 소유자 정보를 CA가 보증 (X.509 표준).
  - **CRL**: 인증서 폐기 목록.

`자주 나오는 출제형태:`

- "전자서명이 보장하는 보안 요소 3가지?" → **무결성, 인증, 부인방지**
- "공개키를 안전하게 배포·관리하기 위한 기반 구조는?" → **PKI**
- "공개키와 소유자 정보를 보증하는 CA 발급 문서는?" → **인증서(Certificate)**

`핵심 답/암기:` 전자서명=개인키 서명·공개키 검증(무결성·인증·부인방지, 기밀성 X). PKI=CA·RA·인증서(X.509).
